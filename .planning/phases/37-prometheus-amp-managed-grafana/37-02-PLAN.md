<task type="auto">
  <name>Task 1: Add Prometheus sidecar to CDK user-data and update docker-compose</name>
  <files>infra/cdk/lib/prediction-stack.ts, docker-compose.yml</files>
  <action>
Modify the CDK user-data in prediction-stack.ts to add two new sections AFTER the fetch-secrets.sh creation and BEFORE the docker-compose.yml write:

1. **Retrieve AMP workspace ID from SSM and write prometheus.yml:**
```
# === Retrieve AMP workspace ID and write Prometheus config ===
AMP_WORKSPACE_ID=$(aws ssm get-parameter --name /prediction/amp-workspace-id --region us-east-1 --query Parameter.Value --output text)

cat > /opt/prediction/prometheus.yml <<PROMEOF
global:
  scrape_interval: 15s
  evaluation_interval: 15s
  external_labels:
    cluster: prediction-prod
    instance: ec2

scrape_configs:
  - job_name: prediction
    static_configs:
      - targets: ['prediction:9000']
    scrape_interval: 15s
    metrics_path: /metrics

remote_write:
  - url: https://aps-workspaces.us-east-1.amazonaws.com/workspaces/${AMP_WORKSPACE_ID}/api/v1/remote_write
    queue_config:
      max_samples_per_send: 1000
      max_shards: 200
      capacity: 2500
    sigv4:
      region: us-east-1
PROMEOF
```

2. **Update the docker-compose.yml heredoc in user-data** to add the prometheus service:
```yaml
  prometheus:
    image: prom/prometheus:v3.10.0
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.retention.time=2h'
      - '--web.enable-lifecycle'
    volumes:
      - /opt/prediction/prometheus.yml:/etc/prometheus/prometheus.yml:ro
    depends_on:
      prediction:
        condition: service_healthy
    restart: "no"
```

3. **Update the local docker-compose.yml** in the repo root to also include the prometheus service (for local development reference). Use the same service definition but with a note that the prometheus.yml path differs locally vs production.

IMPORTANT:
- Scrape target MUST be `prediction:9000` (docker-compose DNS), NOT localhost or port 9001
- `restart: "no"` matches the existing prediction service pattern (systemd manages restarts)
- `--storage.tsdb.retention.time=2h` keeps local TSDB minimal since AMP is the durable store
- The `depends_on` with `condition: service_healthy` ensures prediction is up before scraping starts
- The `${AMP_WORKSPACE_ID}` in the heredoc must NOT be escaped -- it must expand from the shell variable set above

Run `cd infra/cdk && npx cdk synth --quiet` to verify the template synthesizes.

  <name>Task 2: Deploy CDK and verify metrics pipeline end-to-end</name>
  <files>infra/cdk/lib/prediction-stack.ts</files>
  <action>
1. Deploy the updated CDK stack: `cd infra/cdk && npx cdk deploy --require-approval never`
   This will trigger EC2 instance replacement (user-data change = new instance).

2. Wait for the instance to boot and services to start (~3-5 minutes). Monitor via:
   `aws ssm start-session --target INSTANCE_ID` (get instance ID from CDK output)
   Then check: `systemctl status prediction` and `docker compose -f /opt/prediction/docker-compose.yml ps`

3. Verify Prometheus is running and scraping:
   - Check prometheus container logs: `docker compose -f /opt/prediction/docker-compose.yml logs prometheus`
   - Look for "Server is ready to receive web requests" and successful scrape messages
   - Look for NO remote_write errors (403, timeout, connection refused)

4. Verify metrics are flowing to AMP by querying AMP:
   `aws amp query --workspace-id WORKSPACE_ID --region us-east-1 --query-string 'up' --type instant`
   This should return the `up` metric from the prediction job.

5. If Prometheus shows remote_write errors:
   - 403: Check EC2 instance role has AmazonPrometheusRemoteWriteAccess (already attached in Phase 34)
   - Timeout: Check security group allows outbound HTTPS (already allowAllOutbound: true)
   - Connection refused: Verify AMP workspace is ACTIVE
  </action>
  <verify>

2. Prometheus logs show successful scrapes (no target DOWN errors).
3. Prometheus logs show successful remote_write (no 4xx/5xx errors).
4. AMP query for `up` metric returns results.
  </verify>
