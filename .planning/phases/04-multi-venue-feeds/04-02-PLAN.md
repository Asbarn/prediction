    **Auth module** in `src/feed/kalshi/auth.rs`:
    - `fn load_kalshi_private_key(pem_str: &str) -> Result<RsaPrivateKey>`: parse PEM-encoded RSA private key using `rsa::RsaPrivateKey::from_pkcs8_pem`
    - `fn sign_kalshi_request(private_key: &RsaPrivateKey, timestamp_ms: i64, method: &str, path: &str) -> Result<String>`:
      1. Build message: `"{timestamp_ms}{method}{path}"` (no query params)
      2. Sign with `rsa::pss::BlindedSigningKey::<Sha256>` + `RandomizedSigner::sign_with_rng`
      3. Base64-encode the signature using `base64::engine::general_purpose::STANDARD`
      4. Return the base64 string
    - **CRITICAL (Pitfall 4):** Timestamp MUST be in milliseconds. Use `chrono::Utc::now().timestamp_millis()`.
    - Add `#[cfg(test)]` tests: generate a test RSA key, sign a message, verify the signature is non-empty base64.

    **Message types** in `src/feed/kalshi/messages.rs`:
    - `KalshiMessage` enum (tagged by some discriminator field):
      - `OrderbookSnapshot`: `market_ticker: String`, `yes: Vec<[i64; 2]>`, `no: Vec<[i64; 2]>` (price_cents, quantity)
      - `OrderbookDelta`: `market_id: String`, `price: i64`, `delta: i64`, `side: String` ("yes" or "no"), `seq: Option<u64>`
      - `Subscribed`: `id: i64`, `msg: String` -- subscription acknowledgment
      - `Error`: `code: Option<i64>`, `msg: String`
    - Use `#[serde(tag = "type")]` if Kalshi tags messages, or an untagged enum with a wrapper that inspects the JSON structure.
    - Since Kalshi WS message format has some uncertainty (research Open Question 2/3), be defensive: attempt structured parse, fall back to logging the raw JSON on unknown messages.
    - Add unit tests for parsing sample orderbook_snapshot and orderbook_delta JSON.

    **WebSocket client** in `src/feed/kalshi/client.rs`:
    - `KalshiClient` struct: `config: KalshiConfig`, `api_key_id: String`, `private_key: RsaPrivateKey`, `cancel: CancellationToken`
    - `start(&self) -> Result<mpsc::Receiver<RawMessage>>`:
      1. Generate fresh timestamp_ms and signature via `sign_kalshi_request`
      2. Build `http::Request` with headers: `KALSHI-ACCESS-KEY`, `KALSHI-ACCESS-SIGNATURE`, `KALSHI-ACCESS-TIMESTAMP`, plus required WebSocket upgrade headers (`Sec-WebSocket-Key`, `Sec-WebSocket-Version: 13`, `Connection: Upgrade`, `Upgrade: websocket`, `Host`)
      3. Connect via `tokio_tungstenite::connect_async(request)` -- **Pitfall 6:** Auth headers required even for public channels
      4. Send subscribe command: `{"id": 1, "cmd": "subscribe", "params": {"channels": ["orderbook_delta"], "market_ticker": "<ticker>"}}`
      5. Spawn reader task: read frames, wrap in RawMessage, send through channel
      6. Handle connection errors gracefully (supervisor handles retry)
    - Channel buffer: 1024
    - No separate PING task needed (Kalshi heartbeat is staleness-based per research Open Question 5)

    - `apply_snapshot(&mut self, yes: &[(i64, i64)], no: &[(i64, i64)])`: clear both maps, insert all levels
    - `apply_delta(&mut self, side: &str, price: i64, delta: i64)`: add delta to entry, remove if result <= 0
    - `best_yes_bid(&self) -> Option<(i64, i64)>`: `.iter().last()` -- **Pitfall 3:** BTreeMap sorted ascending, best bid is LAST
    - `best_no_bid(&self) -> Option<(i64, i64)>`: `.iter().last()`
    - `best_yes_ask_from_no(&self) -> Option<i64>`: `100 - best_no_bid.price` -- **Pitfall 2:** asks derived from complementary side
    - `best_no_ask_from_yes(&self) -> Option<i64>`: `100 - best_yes_bid.price`
    - `yes_depth(&self) -> Vec<(i64, i64)>`: all yes_bids sorted descending (reverse iter)
    - `no_depth(&self) -> Vec<(i64, i64)>`: all no_bids sorted descending
    - `is_empty(&self) -> bool`
    - Add `#[cfg(test)]` tests:
      - Apply snapshot then verify best bid/ask
      - Apply delta that removes a level (result <= 0)
      - Verify ascending sort means `.last()` is best
      - Verify ask derivation from complementary side

    **Processor** in `src/feed/kalshi/normalize.rs`:
    - `KalshiProcessor` struct:
      - `raw_rx: mpsc::Receiver<RawMessage>` (from client)
      - `snapshot_tx: mpsc::Sender<MarketSnapshot>` (to downstream)
      - `recorder: Option<mpsc::Sender<RecordLine>>` (recording)
      - `cancel: CancellationToken`
      - `staleness_threshold_ms: u64`
      - `books: HashMap<String, KalshiBook>` -- per-market book state
      - Sequence counter: `AtomicU64`
    - `new()` returns `(KalshiProcessor, mpsc::Receiver<MarketSnapshot>)`
    - `run(self)` async method:
      1. Receive `RawMessage` from `raw_rx`
      2. Parse as `KalshiMessage`
      3. For `OrderbookSnapshot`: create/replace `KalshiBook` for market, apply snapshot, produce `MarketSnapshot`
      4. For `OrderbookDelta`: get or create book, apply delta, produce `MarketSnapshot`
      5. **Normalization (Pattern 4 from research):**
         - `fn cents_to_probability(cents: i64) -> Decimal { Decimal::new(cents, 2) }` -- 42 cents -> 0.42
         - For YES contract view: `bid = best_yes_bid`, `ask = best_yes_ask_from_no` (derived), `bid_probability = cents_to_probability(bid)`, `ask_probability = cents_to_probability(ask)`
         - Depth: YES bids converted to `(Price, Notional)`, YES asks derived from NO bids
         - `instrument_id` from `market_ticker`
         - Greeks/ticker fields: all `None`
      6. Staleness gate: parse Kalshi timestamp, if age > threshold set `is_stale = true`
      7. Record raw message via recorder
    - Add metrics: `counter!("kalshi_messages_total")`, `histogram!("kalshi_latency_ms")`
    - Add `#[cfg(test)]` tests:
      - Process a snapshot message and verify MarketSnapshot probability values
      - Verify cents-to-probability conversion accuracy (42 -> 0.42, 99 -> 0.99)
      - Verify ask derivation: YES ask = (100 - best NO bid) cents

      - Creates fresh `KalshiClient` per attempt (fresh auth signature generated each time since timestamp is part of signing message)

    - Use `config.reconnect` for backoff parameters
