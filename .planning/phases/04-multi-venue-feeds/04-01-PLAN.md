    **Message types** in `src/feed/polymarket/messages.rs`:
    - `PolymarketEvent` enum: `Book(PolymarketBookEvent)`, `PriceChange(PolymarketPriceChange)`, `Unknown(serde_json::Value)` -- use `#[serde(tag = "event_type")]` with rename_all
    - `PolymarketBookEvent`: `asset_id: String`, `market: String`, `hash: String`, `bids: Vec<PriceLevel>`, `asks: Vec<PriceLevel>`, `timestamp: String`

    - `PolymarketPriceChange`: `market: String`, `price_changes: Vec<PriceChangeEntry>`, `timestamp: String`
    - `PriceChangeEntry`: `asset_id: String`, `price: String`, `size: String`, `side: String`, `best_bid: String`, `best_ask: String`

    **IMPORTANT (Pitfall 5):** Polymarket WS frames can be JSON arrays. The client must handle both `[{...}, {...}]` and `{...}` formats. Parse raw text: if starts with `[`, parse as `Vec<PolymarketEvent>`, else parse as single `PolymarketEvent`.

    **WebSocket client** in `src/feed/polymarket/client.rs`:
    - `PolymarketClient` struct with `config: PolymarketConfig`, `cancel: CancellationToken`
    - `start(&self) -> Result<mpsc::Receiver<RawMessage>>`:
      1. Connect to `config.ws_url` via `tokio_tungstenite::connect_async`
      2. Send subscribe message: `{"assets_ids": [<token_ids from config>], "type": "market"}`
      3. Spawn reader task that: reads WS frames, wraps in `RawMessage` with `DualTimestamp::now()`, sends through channel
      4. Spawn PING task: send WebSocket PING frame every `config.ping_interval_ms` (Polymarket heartbeat protocol)
      5. Handle WS Close/errors gracefully -- log and drop channel (supervisor handles reconnection)
    - No authentication needed for market channel (public data)
    - Channel buffer size: 1024 (same as Deribit)

    **Module** `src/feed/polymarket/mod.rs`: export `pub mod client; pub mod messages; pub mod normalize; pub mod supervisor;`

  <action>
    **Processor** in `src/feed/polymarket/normalize.rs`:
    - `PolymarketProcessor` struct following the DeribitProcessor pattern:
      - `raw_rx: mpsc::Receiver<RawMessage>` (from client)
      - `snapshot_tx: mpsc::Sender<MarketSnapshot>` (to downstream fan-in channel)
      - `recorder: Option<mpsc::Sender<RecordLine>>` (to recording service)
      - `cancel: CancellationToken`
      - `staleness_threshold_ms: u64`
      - Internal sequence counter: `AtomicU64`
    - `new()` returns `(PolymarketProcessor, mpsc::Receiver<MarketSnapshot>)` -- creates internal snapshot channel (256 buffer)
    - `run(self)` async method:
      1. Receive `RawMessage` from `raw_rx`
      2. Parse raw text handling array vs single object (Pitfall 5)
      3. For each `PolymarketEvent::Book`:
         - Parse bids/asks `PriceLevel.price` strings to `Decimal` via `Decimal::from_str`
         - Best bid = first bid (Polymarket sorts descending), Best ask = first ask (ascending)
         - **Polymarket prices ARE probabilities** (Pattern 3 from research): `bid_probability = bid price`, `ask_probability = ask price`
         - Build `MarketSnapshot` with: `venue: Venue::Polymarket`, `instrument_id` from `asset_id`, `bid`/`ask` as `Price::new(decimal)`, `bid_probability`/`ask_probability` as `Probability::new(decimal)`, full `depth_bids`/`depth_asks` from all levels
         - Parse `timestamp` string to `exchange_timestamp` (milliseconds as i64)
         - Apply staleness gate: if `now_ms - exchange_timestamp > staleness_threshold_ms`, set `is_stale = true` (same OR logic as Deribit)
         - Greeks/ticker fields: all `None` (Polymarket has no options data)
         - Send `MarketSnapshot` via `snapshot_tx`
      4. For `PolymarketEvent::PriceChange`: log at debug level. In Phase 4, we rely on full book snapshots for accuracy. PriceChange events could be used for incremental updates in the future.
      5. Record raw message via recorder (same RecordLine pattern as Deribit: venue=Polymarket, channel="book" or "price_change", instrument=asset_id)
    - Add metrics: `counter!("polymarket_messages_total")`, `histogram!("polymarket_latency_ms")`, `gauge!("polymarket_book_events")`

    **Supervisor** in `src/feed/polymarket/supervisor.rs`:
    - `PolymarketSupervisor` struct: near-identical to `DeribitSupervisor` but wrapping `PolymarketClient`
    - Constructor: `new(config: PolymarketConfig, cancel: CancellationToken)`
    - `run(self, tx: mpsc::Sender<RawMessage>)`: exponential backoff loop using `backoff` crate, same pattern as DeribitSupervisor:
      1. Create fresh `PolymarketClient` per attempt
      2. Forward messages from client to `tx`
      3. Reset backoff on first message received (not on connection success)
      4. On disconnect, apply backoff and retry
    - No rate limiter needed for Polymarket (public read-only channel, no outbound rate concern beyond subscribe)
    - Use `config.reconnect` for backoff parameters (same `ReconnectConfig` struct)

    Add `#[cfg(test)]` tests in normalize.rs:
    - Test parsing and normalizing a sample book event JSON into MarketSnapshot
    - Verify bid/ask probability values match the price strings
    - Verify staleness detection when exchange_timestamp is old
