<task type="auto">
  <name>Task 1: Deploy CDK, rebuild image, and redeploy container</name>
  <files></files>
  <action>
1. Deploy CDK changes to apply the IAM policy addition and updated user-data:
   ```bash
   cd infra/cdk && npx cdk diff && npx cdk deploy --require-approval never
   ```
   The diff should show: CloudWatchAgentServerPolicy added to instance role, and updated user-data with awslogs driver.

   Note: The user-data change alone does NOT take effect on a running instance. User-data only runs on first boot. The awslogs driver change is embedded in the docker-compose written by user-data. To apply it to the running instance, we must update the docker-compose file on the instance directly via SSM.

2. Get the instance ID from CDK outputs or AWS CLI:
   ```bash
   INSTANCE_ID=$(aws cloudformation describe-stacks --stack-name PredictionStack --query "Stacks[0].Outputs[?OutputKey=='InstanceId'].OutputValue" --output text --region us-east-1)
   ```

3. Update the docker-compose.yml on the running instance via SSM to use awslogs driver. Write the updated compose file using SSM send-command, replacing the json-file logging block with the awslogs configuration (awslogs-region: us-east-1, awslogs-group: /prediction/production, awslogs-stream-prefix: prediction, mode: non-blocking, max-buffer-size: 4m).

4. Build and push the new Docker image with JSON stdout changes:
   ```bash
   docker build -t prediction:latest .
   docker tag prediction:latest 606103597377.dkr.ecr.us-east-1.amazonaws.com/prediction:latest
   aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 606103597377.dkr.ecr.us-east-1.amazonaws.com
   docker push 606103597377.dkr.ecr.us-east-1.amazonaws.com/prediction:latest
   ```

5. Restart the container on EC2 via SSM to pull the new image and use the updated compose config:
   ```bash
   aws ssm send-command \
     --instance-ids "$INSTANCE_ID" \
     --document-name "AWS-RunShellScript" \
     --parameters 'commands=["cd /opt/prediction && docker compose down && /opt/prediction/fetch-secrets.sh && docker compose pull && docker compose up -d"]' \
     --region us-east-1
   ```
   Wait 30-60 seconds for the container to start and begin emitting logs.

6. Restart the CloudWatch Agent on the instance so it picks up the new IAM permissions:
   ```bash
   aws ssm send-command \
     --instance-ids "$INSTANCE_ID" \
     --document-name "AWS-RunShellScript" \
     --parameters 'commands=["/opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -a stop && /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -a fetch-config -m ec2 -s -c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json"]' \
     --region us-east-1
   ```
  </action>
  <verify>
After the container is running with the new image and awslogs driver, verify:

1. Check container is running via SSM:
   ```bash
   aws ssm send-command --instance-ids "$INSTANCE_ID" --document-name "AWS-RunShellScript" --parameters 'commands=["docker compose -f /opt/prediction/docker-compose.yml ps"]' --region us-east-1
   ```

2. Check CloudWatch Logs have recent entries:
   ```bash
   aws logs tail /prediction/production --since 5m --region us-east-1 | head -20
   ```
   Should show JSON-formatted log lines with `timestamp`, `level`, `target` fields.

3. Verify structured querying works via Logs Insights:
   ```bash
   aws logs start-query \
     --log-group-name /prediction/production \
     --start-time $(date -d '10 minutes ago' +%s) \
     --end-time $(date +%s) \
     --query-string 'fields @timestamp, level, target | sort @timestamp desc | limit 10' \
     --region us-east-1
   ```
   Then retrieve results with `aws logs get-query-results --query-id <id>`.

4. Verify CloudWatch Agent host metrics:
   ```bash
   aws cloudwatch list-metrics --namespace "Prediction/EC2" --region us-east-1
   ```
   Should list metrics like `mem_used_percent`, `cpu_usage_user`, `disk_used_percent`.
  </verify>
