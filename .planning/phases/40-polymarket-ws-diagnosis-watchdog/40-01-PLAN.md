<task type="auto">
  <name>Task 2: Create Polymarket WS diagnostic integration test</name>
  <files>tests/polymarket_diag.rs</files>
  <action>
Create `tests/polymarket_diag.rs` as an `#[ignore]` integration test designed to be run manually from EC2 (or any host) to diagnose the Polymarket WS failure mode.

The test function `diagnose_polymarket_ws_from_this_host` should:

1. **REST baseline check**: Send GET to `https://clob.polymarket.com/midpoint?token_id={TOKEN_ID}` using reqwest. Print the response status and body. This confirms the host can reach Polymarket REST API.

2. **Fetch an active token_id**: Query `https://gamma-api.polymarket.com/markets?closed=false&limit=1` to get a currently active market's token_id. This avoids using hardcoded placeholder IDs from config. Parse the JSON response to extract `clob_token_ids[0]`. If this fails, fall back to a hardcoded well-known token_id with a warning.

3. **WS connection test**: Attempt `tokio_tungstenite::connect_async("wss://ws-subscriptions-clob.polymarket.com/ws/market")`.
   - If connection fails: Print `DIAGNOSIS: Connection failed: {error}` -- this indicates connection reset or geo-block.
   - If connected: Send subscription message `{"type": "market", "assets_ids": ["{token_id}"]}` (note: Polymarket uses `assets_ids` not `asset_ids`).

4. **Data reception test**: Wait up to 30 seconds (`tokio::time::timeout`) for the first WS text message.
   - Message received: Print `DIAGNOSIS: WS working! Received: {first 200 chars of message}`.
   - Timeout (no message): Print `DIAGNOSIS: Silent freeze detected -- connected and subscribed but no data in 30s (GitHub #292)`.
   - Read error: Print `DIAGNOSIS: Read error after connect: {error}`.
   - Stream ended: Print `DIAGNOSIS: Connection closed by server immediately after subscribe`.

5. **Summary**: Print a clear one-line verdict: `VERDICT: {WORKING|CONNECTION_FAILED|SILENT_FREEZE|READ_ERROR|CLOSED_BY_SERVER}`.

Use `println!` (not tracing) for all output since this is a diagnostic tool.

Use `futures_util::StreamExt` for `ws_stream.next()` and `futures_util::SinkExt` for `ws_stream.send()`. Use `tokio_tungstenite::tungstenite::Message` for WS message types.

Do NOT import anything from the main crate -- this is a standalone integration test using only third-party crates that are already workspace dependencies (tokio, tokio-tungstenite, reqwest, futures-util, serde_json).
  </action>
  <verify>Run `cargo test --test polymarket_diag --no-run` -- must compile without errors. Do NOT run the actual test (it requires network/EC2). Run `cargo test --test polymarket_diag -- --list` to verify the test function is discoverable.</verify>
  <done>Diagnostic test compiles, is listed as an ignored test, and covers all failure modes: connection failure, silent freeze, working, read error, and server close. Test can be run from EC2 with `cargo test --test polymarket_diag -- --ignored --nocapture`.</done>
</task>
