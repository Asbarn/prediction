    **1. Create `src/feed/deribit/normalize.rs`:**
    This is the processor task from the research architecture:
    ```
    [WS Reader] --raw frames--> mpsc(1024) --> [Processor Task]
                                                  |
                                mpsc(256) <-------+-----> mpsc(8192) --> [Recorder Task]
                                (snapshots)               (to disk, Plan 03)
    ```

    Implement `DeribitProcessor` struct that:
    - Takes: `mpsc::Receiver<RawMessage>` (from DeribitClient), `mpsc::Sender<MarketSnapshot>` (downstream), optional `mpsc::Sender<RecordLine>` (recording, wired in Plan 03), `CancellationToken`
    - Maintains: `HashMap<InstrumentId, InstrumentBook>` for per-instrument book state
    - Maintains: `HashMap<InstrumentId, TickerState>` for latest ticker data per instrument (mark_price, greeks, etc.)
    - Maintains: `AtomicU64` sequence counter for MarketSnapshot.sequence

    Implement a `run()` method that loops:
    1. Receives `RawMessage` from the input channel (or cancellation)
    2. Parses the raw text as `DeribitMessage` via `serde_json::from_str`
       - On parse error: log warning with the raw text (truncated), increment error counter, continue
    3. If `DeribitMessage::Response`: log the response (subscribe confirmation or error). Do not produce a snapshot.
    4. If `DeribitMessage::Notification`: extract the channel name and data
       - Parse channel name via `ChannelKind::parse(channel)`
       - Route to the appropriate handler:

    **Book handler (`ChannelKind::Book`):**
    - Deserialize `data` as `BookData` via `serde_json::from_value`
    - Get or create `InstrumentBook` for the instrument
    - Call `book.apply_snapshot(&data, raw_msg.received_at)`
    - On `SequenceError::Gap`: log error, mark stale, attempt re-subscribe (send re-subscribe request if write half is available -- or just log and mark stale in Phase 2, re-subscribe mechanism comes in Phase 3). For Phase 2: just log the gap and mark stale. Do NOT attempt re-subscribe yet.
    - On success: build a `MarketSnapshot` from the updated book state + latest ticker state
    - Send snapshot to downstream channel

    **Ticker handler (`ChannelKind::Ticker`):**
    - Deserialize `data` as `TickerData`
    - Update the `TickerState` for the instrument (store mark_price, index_price, greeks, etc.)
    - Build a `MarketSnapshot` merging book + ticker state
    - Send snapshot to downstream channel
    - This means every ticker update also produces a snapshot (with latest book depth + new ticker data)

    **Trades handler (`ChannelKind::Trades`):**
    - Deserialize `data` as `Vec<TradeData>` (trades come as arrays)
    - Log trade activity at debug level (instrument, price, amount, direction)
    - Do NOT produce a MarketSnapshot for trades in Phase 2. Trades are recorded (Plan 03) but do not drive snapshot updates. Phase 6 may use trade data for volume profiling.

    **Price index handler (`ChannelKind::PriceIndex`):**
    - Deserialize `data` as `PriceIndexData`
    - Store latest index price (will be used in Phase 7 for Black-76 forward price)
    - Log at debug level
    - Do NOT produce a MarketSnapshot -- this is reference data

    **Building a MarketSnapshot:**
    Create a helper function `build_snapshot(instrument: &InstrumentId, book: &InstrumentBook, ticker: Option<&TickerState>, sequence: u64, received_at: DualTimestamp) -> MarketSnapshot` that:
    - Sets venue to `Venue::Deribit`
    - Sets bid/ask from book.best_bid()/best_ask()
    - Sets depth_bids/depth_asks from book.bids/book.asks (cloned)
    - Sets greeks, mark_price, index_price, mark_iv from ticker state (if available)
    - Sets exchange_timestamp from the BookData or TickerData timestamp
    - Sets is_stale from book.is_stale
    - Converts f64 prices to `Price(Decimal)` using `Decimal::try_from(f64).unwrap_or_else(|_| Decimal::from_f64_retain(f64_val).unwrap())` -- use `from_f64_retain` as fallback to avoid panics on edge-case floats
    - Sets sequence from atomic counter (increment on each snapshot)
    - Sets trace_id from `TraceId::new()`

    **Recording fan-out:**
    If the optional recording sender is present, for every incoming `RawMessage`, create a `RecordLine` and send via `try_send`. The `RecordLine` type will be defined in Plan 03 -- for now, accept `Option<mpsc::Sender<RecordLine>>` in the constructor but gate behind a compile-time cfg or just use a placeholder type. Actually, better approach: accept `Option<mpsc::Sender<(String, DualTimestamp, String, Option<String>)>>` as a generic recording tuple (raw_text, timestamp, channel, instrument) that Plan 03 will refine. Or simplest: define `RecordLine` in `src/feed/traits.rs` now since it is part of the `Recorder` trait contract anyway.
