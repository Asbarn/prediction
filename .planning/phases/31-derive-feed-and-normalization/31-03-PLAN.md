<task type="auto">
  <name>Task 1: Create DeriveClient WebSocket client</name>
  <files>src/feed/derive/client.rs</files>
  <action>
    Create `src/feed/derive/client.rs` adapted from `src/feed/deribit/client.rs` with these Derive-specific simplifications:

    **Struct:** `DeriveClient` with fields:
    - `config: DeriveConfig`
    - `instruments: Vec<String>`
    - `cancel: CancellationToken`
    - `rate_limiter: Option<VenueRateLimiter>`

    **Constructor:** `DeriveClient::new(config, instruments, cancel, rate_limiter) -> Self`

    **Method:** `pub async fn run(self) -> mpsc::Receiver<RawMessage>`
    1. Spawn a tokio task that:
       a. Connects to `config.ws_url` using `tokio_tungstenite::connect_async`
       b. Constructs subscribe message using `channels::build_subscription_channels(&self.instruments, self.config.book_depth)` with JSON-RPC 2.0 format:
          ```json
          {"jsonrpc": "2.0", "id": <atomic_id>, "method": "subscribe", "params": {"channels": [...]}}
          ```
          NOTE: method is `"subscribe"` NOT `"public/subscribe"` (Derive difference from Deribit)
       c. Sends subscribe message (rate-limited if limiter present)
       d. Enters read loop: for each text frame, wraps in `RawMessage { text, received_at: DualTimestamp::now() }` and sends to mpsc channel
       e. Dead connection timeout: 60 seconds with no message received -> break from loop (Derive uses WS PING/PONG, no application heartbeat needed)
       f. On cancel token trigger, break from loop

    **Key differences from DeribitClient:**
    - NO `set_heartbeat` request after connect
    - NO `test_request` response handling
    - NO heartbeat timeout tracking (replaced by simple 60s message timeout)
    - Subscribe method is `"subscribe"` not `"public/subscribe"`
    - Only 2 channel types per instrument (orderbook + ticker_slim) vs Deribit's 4

    Use `static REQUEST_ID: AtomicU64` for JSON-RPC request IDs (same pattern as Deribit).
    Use `const RAW_MESSAGE_BUFFER: usize = 1024` for channel capacity.
    Use `tracing::{info, warn, debug}` for logging with `venue = "derive"` field.
  </action>
  <verify>
    `cargo check` passes with DeriveClient compiling correctly.
    No warnings in new code.
  </verify>
  <done>
    DeriveClient connects to Derive WebSocket, subscribes to orderbook+ticker_slim channels with correct JSON-RPC format, forwards raw text frames, and detects dead connections via 60s timeout. No heartbeat protocol complexity.
  </done>

  <action>
    Create `src/feed/derive/supervisor.rs` adapted from `src/feed/deribit/supervisor.rs`:

    **Struct:** `DeriveSupervisor` with fields:
    - `config: DeriveConfig`
    - `instruments_rx: watch::Receiver<Vec<String>>`
    - `cancel: CancellationToken`
    - `rate_limiter: VenueRateLimiter`
    - `health: Arc<VenueHealth>`

    **Constructor:** `DeriveSupervisor::new(config, instruments_rx, cancel, rate_limiter, health) -> Self`

    **Method:** `pub async fn run(self, raw_tx: mpsc::Sender<RawMessage>)`
    1. Create `ExponentialBackoffBuilder` with:
       - `initial_interval`: from `config.reconnect_delay_ms` (converted to Duration)
       - `max_interval`: 60 seconds
       - `max_elapsed_time`: None (reconnect forever)
    2. Reconnection loop:
       a. Get current instrument list from `instruments_rx.borrow().clone()`
       b. If instruments list is empty, sleep 1 second and continue (nothing to subscribe to)
       c. Create `DeriveClient::new(config.clone(), instruments, cancel.child_token(), rate_limiter.clone())`
       d. Call `client.run()` to get receiver
       e. Forward messages from client receiver to `raw_tx`
       f. On client exit (receiver closed), mark `health` as disconnected
       g. Check cancel token -- if cancelled, break
       h. Apply backoff delay, log reconnection attempt
       i. Reset backoff on successful connection (received at least one message)
    3. Also select on `instruments_rx.changed()` -- when instrument list updates:
       - Log the change
       - Drop current client (cancel its child token)
       - Immediately reconnect with new instrument list (reset backoff)

    **Key difference from DeribitSupervisor:** No heartbeat-related logic. The supervisor is structurally identical otherwise.

    **Update `src/feed/derive/mod.rs`**: Add `pub mod client;` and `pub mod supervisor;` to the module declarations.
  </action>

    No warnings in new code.
  </verify>
  <done>
    DeriveSupervisor wraps DeriveClient with exponential backoff reconnection, accepts dynamic instrument list updates via watch channel, and reports connection health. Structurally identical to DeribitSupervisor minus heartbeat logic.
  </done>
