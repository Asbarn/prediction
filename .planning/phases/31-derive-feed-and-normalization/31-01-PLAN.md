    Create `src/feed/derive/` directory and 3 files:

    **src/feed/derive/mod.rs**: Declare submodules: `pub mod book; pub mod channels; pub mod messages;` (client, supervisor, normalize added in later plans).

    **src/feed/mod.rs**: Add `pub mod derive;` to existing module declarations.

    **src/feed/derive/messages.rs**: Define Derive-specific message types adapted from `src/feed/deribit/messages.rs` but with critical Derive differences:

    1. `DeriveMessage` enum with `#[serde(untagged)]` - only 2 variants (no heartbeat):
       - `Response(DeriveRpcResponse)` - subscribe confirmation
       - `Notification(DeriveRpcNotification)` - subscription data

    2. `DeriveRpcResponse` struct with `id: i64`, `result: serde_json::Value`

    3. `DeriveRpcNotification` struct with `method: String`, `params: DeriveNotificationParams`

    4. `DeriveNotificationParams` with `channel: String`, `data: serde_json::Value` (data is deserialized further by the processor based on channel kind)

    5. `DeriveBookData` struct: `timestamp: i64`, `instrument_name: String`, `publish_id: i64`, `bids: Vec<[String; 2]>`, `asks: Vec<[String; 2]>`. All prices/amounts are strings per API findings.

    6. `DeriveTickerSlimWrapper` struct: `timestamp: i64`, `instrument_ticker: DeriveTickerSlimData` (the outer wrapper -- Pitfall 6 from research).

    7. `DeriveTickerSlimData` struct with `#[serde(rename)]` on all fields: `t` (timestamp), `A` (best_ask_amount), `a` (best_ask_price), `B` (best_bid_amount), `b` (best_bid_price), `I` (index_price), `M` (mark_price), `option_pricing: Option<DeriveOptionPricing>`. All string fields are `Option<String>` to handle nulls (Pitfall 1).

    8. `DeriveOptionPricing` struct with `#[serde(rename)]`: `d` (delta), `t` (theta), `g` (gamma), `v` (vega), `i` (iv), `r` (rate), `f` (forward), `m` (mark_price), `df` (discount_factor), `bi` (bid_iv), `ai` (ask_iv). All `Option<String>`.

    Add unit tests:
    - Deserialize the exact orderbook JSON from DERIVE-API-FINDINGS.md into `DeriveBookData`
    - Deserialize the exact ticker_slim JSON from DERIVE-API-FINDINGS.md into `DeriveTickerSlimWrapper`
    - Verify null `f` field at top level deserializes correctly (Pitfall 1)
    - Verify `DeriveMessage` enum routes response vs notification correctly

    **src/feed/derive/channels.rs**: Define channel construction and parsing:

    1. `DeriveChannelKind` enum: `Orderbook`, `TickerSlim`, `Unknown(String)` with `parse(channel: &str) -> Self`

    2. `build_subscription_channels(instruments: &[String], book_depth: u32) -> Vec<String>`: for each instrument, produce `orderbook.{inst}.10.{book_depth}` and `ticker_slim.{inst}.100`

    3. `extract_instrument(channel: &str) -> Option<String>`: for orderbook channels, use `rsplitn(3, '.')` to strip group+depth suffix. For ticker_slim, use `rsplit_once('.')` to strip interval. (Pitfall 5 -- instrument names contain dashes)

    Add unit tests:
    - `build_subscription_channels` produces correct channel names
    - `extract_instrument` correctly extracts `BTC-20260305-69500-P` from `orderbook.BTC-20260305-69500-P.10.10`
    - `extract_instrument` correctly extracts from `ticker_slim.BTC-20260305-69500-P.100`
    - `DeriveChannelKind::parse` identifies orderbook, ticker_slim, and unknown channels

<task type="auto">
  <name>Task 2: Create DeriveBook snapshot-only book state</name>
  <files>src/feed/derive/book.rs</files>
  <action>
    Create `src/feed/derive/book.rs` adapted from `src/feed/deribit/book.rs` but SIMPLER (no delta reconciliation, no change_id sequencing):

    1. `DeriveBook` struct with fields: `instrument: String`, `bids: Vec<(Decimal, Decimal)>` (price, amount), `asks: Vec<(Decimal, Decimal)>`, `last_publish_id: Option<i64>`, `last_timestamp: Option<i64>`, `is_stale: bool`.

    2. `DeriveBook::new(instrument: String) -> Self` -- empty book.

    3. `DeriveBook::apply_snapshot(&mut self, data: &DeriveBookData)` -- replaces full state:
       - Parse each `[price_str, amount_str]` pair using `Decimal::from_str()` (not f64 -- Pitfall: precision)
       - Filter out any pairs that fail to parse (log at debug level)
       - Sort bids descending by price, asks ascending by price
       - Update `last_publish_id` and `last_timestamp` from data
       - Set `is_stale = false`

    4. `DeriveBook::best_bid(&self) -> Option<(Decimal, Decimal)>` -- first bid (highest price)

    5. `DeriveBook::best_ask(&self) -> Option<(Decimal, Decimal)>` -- first ask (lowest price)

    6. `DeriveBook::mark_stale(&mut self)` -- sets `is_stale = true`

    Use `rust_decimal::Decimal` and `std::str::FromStr` for parsing. Import `DeriveBookData` from `super::messages`.

    Add unit tests:
    - `apply_snapshot` correctly parses string prices to Decimal and sorts bids/asks
    - `best_bid`/`best_ask` return correct top-of-book after apply_snapshot
    - Invalid price strings are filtered out gracefully (no panic)
    - Empty book returns None for best_bid/best_ask
    - Successive snapshots fully replace state (no stale data from prior snapshot)
    - `mark_stale` sets the flag correctly
  </action>
  <verify>
    `cargo test --lib feed::derive::book` passes.
    `cargo check` passes with zero new warnings.
  </verify>
  <done>
    DeriveBook stores snapshot-only order book state, parses string prices to Decimal, sorts correctly, and handles edge cases. No delta/sequence logic (intentionally simpler than DeribitBook).
