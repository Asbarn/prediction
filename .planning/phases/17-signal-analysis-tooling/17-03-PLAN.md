   ```rust
       pub pattern: SpreadPattern,
       pub threshold_status: ThresholdStatus,

   }
   ```

2. Define `FilteredSignalTracker`:
   ```rust
   pub struct FilteredSignalTracker {
       /// Filtered signals keyed by event_id, capped per event.
       signals: HashMap<String, Vec<FilteredSignalEntry>>,
       /// Max entries per event_id to prevent unbounded growth.
       max_per_event: usize,
   }
   ```
   Where `FilteredSignalEntry` is:
   ```rust
   #[derive(Debug, Clone, Serialize, Deserialize)]
   pub struct FilteredSignalEntry {
       pub pattern: SpreadPattern,
       pub threshold_status: ThresholdStatus,
       pub net_spread: Decimal,
       pub timestamp_ms: i64,
   }
   ```

3. Implement `FilteredSignalTracker`:
   - `pub fn new(max_per_event: usize) -> Self` -- default max_per_event = 100
   - `pub fn record(&mut self, event: FilteredSignalEvent)`:
     - Get or insert Vec for event_id
     - If Vec length >= max_per_event, remove oldest entry
     - Push new FilteredSignalEntry
   - `pub fn correlate_with_settlement(&mut self, event_id: &str, outcome: &OutcomeKind, positions: &[PaperPosition]) -> Vec<FilteredCorrelation>`:
     - Look up filtered signals for this event_id
     - For each filtered signal: determine hypothetical outcome based on the settlement outcome and the signal's pattern/direction. The signal had a net_spread that it would have earned if the position had been taken and the event settled as it did. Since filtered signals never became positions, we approximate: if the event settled Yes and the pattern was BuyPolyYesSellKalshiYes, the trade direction was "buy poly" -- settlement value 1.0, so hypothetical raw_pnl ~ (1.0 - buy_price) * notional. But we don't have actual fill prices for filtered signals. Instead, use `net_spread` as proxy edge. A simple approach: if the signal's direction would have profited from this outcome, mark as `hypothetical_hit = true`.
     - For each pattern: if outcome is Yes, buying YES at signal's implied buy_price would profit (since settlement = 1.0). If outcome is No, selling YES would profit. Map pattern direction to hit/miss based on outcome.
     - Return `Vec<FilteredCorrelation>` where:
     ```rust
     pub struct FilteredCorrelation {
         pub threshold_status: ThresholdStatus,
         pub net_spread: Decimal,
         pub hypothetical_hit: bool,
         pub timestamp_ms: i64,
     }
     ```
   - `pub fn remove_event(&mut self, event_id: &str)` -- cleanup after settlement correlation
   - `pub fn export_state(&self) -> HashMap<String, Vec<FilteredSignalEntry>>` -- for checkpoint
   - `pub fn import_state(&mut self, state: HashMap<String, Vec<FilteredSignalEntry>>)` -- from checkpoint

4. On `SignalAnalyzer`, add:
   - `filtered_tracker: FilteredSignalTracker` field
   - `pub fn record_filtered_signal(&mut self, event: FilteredSignalEvent)` -- delegates to filtered_tracker
   - `pub fn correlate_filtered_with_settlement(&mut self, event_id: &str, outcome: &OutcomeKind, positions: &[PaperPosition]) -> Vec<FilteredCorrelation>` -- delegates to filtered_tracker, then updates threshold effectiveness accumulators for Filtered/PassedStaticOnly categories
   - Update `emit_prometheus_gauges()` to include threshold effectiveness breakdown -- the accumulators already have threshold_status in their key, so PassedBoth / PassedStaticOnly / Filtered categories are naturally separated in the existing gauges. Add a dedicated gauge:
     - `signal_analysis_filtered_hypothetical_hit_rate{threshold_status}` -- for filtered signals specifically
   - Update `export_state` to include filtered_tracker state
   - Update `import_state` to restore filtered_tracker state
   - Update checkpoint integration (the filtered signals map should be included in checkpoint)
