  <name>Task 1: Extend stats module with Pearson correlation and KS test</name>
  <files>src/analysis/stats.rs</files>
  <action>
Add two functions to the bottom of src/analysis/stats.rs (before the #[cfg(test)] mod tests block):

1. `pub fn pearson_correlation(x: &[f64], y: &[f64]) -> Option<f64>` -- Pearson r between two samples. Returns None if n < 2 or either sample has zero variance. Implementation: single-pass through min(x.len, y.len) pairs computing cov, var_x, var_y. Return cov / (var_x.sqrt() * var_y.sqrt()). Use the exact algorithm from the research code example.

2. `pub struct KsTestResult { pub statistic: f64, pub p_value: f64, pub n1: usize, pub n2: usize }` -- derive Debug, Clone. Implement Serialize (needed for JSON output).

3. `pub fn ks_test_two_sample(sample1: &[f64], sample2: &[f64]) -> Option<KsTestResult>` -- Two-sample KS test. Returns None if either empty. Merge-sort both samples, walk computing ECDF difference, track D_max. Asymptotic p-value: `2 * exp(-2 * n_eff * D^2)` where `n_eff = n1*n2/(n1+n2)`. Clamp p_value to [0, 1]. Use the exact algorithm from the research code example.

Add tests in the existing tests module:
- `pearson_perfect_positive`: [1,2,3,4,5] vs [2,4,6,8,10] -> r = 1.0 (within 1e-10)
- `pearson_perfect_negative`: [1,2,3,4,5] vs [10,8,6,4,2] -> r = -1.0 (within 1e-10)
- `pearson_uncorrelated_returns_near_zero`: use [1,2,3,4,5] vs [2,5,1,4,3]
- `pearson_too_few_returns_none`: empty or single element -> None
- `pearson_zero_variance_returns_none`: [5,5,5] vs [1,2,3] -> None
- `ks_identical_samples`: same data -> statistic near 0, p_value near 1
- `ks_completely_different`: [0,0,0,0,0] vs [1,1,1,1,1] -> statistic = 1.0
- `ks_empty_returns_none`: either empty -> None

Add `use serde::Serialize;` import at the top of stats.rs (only needed for KsTestResult derive).
  </action>

**Step 1: Create src/analysis/cost_audit.rs** (computation logic, no CLI concerns):

Define structs (all derive Debug, Clone, Serialize):
- `CostComponent { name: String, mean: f64, median: f64, std_dev: f64, pct_of_total: f64, sum: f64 }` -- one row per cost component
- `CostAuditResult { signal_count: usize, mean_raw_spread: f64, mean_net_edge: f64, mean_total_cost: f64, components: Vec<CostComponent> }` -- components sorted descending by mean magnitude
- `CostAuditOutput { loading: LoadingSummary, aggregate: CostAuditResult, by_event: Option<BTreeMap<String, CostAuditResult>> }` -- full output wrapper for JSON serialization

Implement `pub fn compute_cost_audit(signals: &[ArbSignal]) -> CostAuditResult`:
- Extract each CostBreakdown field (prediction_fee, options_fee_estimate, carry_cost, prediction_slippage, options_spread_cost, basis_risk_premium, liquidity_factor) into f64 vectors using `to_f64_lossy()` on each Decimal.
- For each component: compute mean (via stats::mean_f64), median (sort + stats::median_f64), stddev (via stats::stddev_f64).
- Compute total_cost mean from cost_breakdown.total_cost field. pct_of_total = component_mean / total_cost_mean * 100 (handle zero total_cost).
- Sort components by mean descending (largest cost contributor first).
- Also compute mean raw_spread and mean net_edge from signal fields.

Implement `pub fn cost_audit_table(result: &CostAuditResult) -> Table`:
- Use `new_table(&["Component", "Mean", "Median", "Std Dev", "% of Total"])`.
- `set_numeric_columns` for columns 1-4.
- Add section header "=== SUMMARY ===" with rows for signal_count, mean_raw_spread, mean_net_edge, mean_total_cost (format to 6 decimal places).
- Add section header "=== COST BREAKDOWN (by magnitude) ===" then one row per component with values formatted to 6 decimal places, pct_of_total to 1 decimal place with "%" suffix.

**Step 2: Update src/analysis/mod.rs** -- add `pub mod cost_audit;` line.

**Step 3: Create src/bin/cost_audit.rs** (thin CLI entry point):

Follow the exact pattern from spread_analytics.rs:
- Clap Parser struct with: `--from`, `--to`, `--last`, `--output` (OutputFormat, default "table"), `--by-event`, `--log-dir` (default "signal_logs").
- `#[command(name = "cost-audit")]` and `#[command(about = "Decompose cost components per signal to identify negative edge sources")]`.
- main(): parse args, create DateRange, get files via `range.files_in_dir(&cli.log_dir)`, load via `load_jsonl::<ArbSignal>(&files)`.
- Build LoadingSummary (count unique event_ids like spread_analytics does).
- Handle empty data: render summary, print "No signal data in range.", return Ok.
- Compute aggregate via `compute_cost_audit(&result.records)`.
- If `--by-event`: group records into BTreeMap<String, Vec<ArbSignal>> by event_id, compute per-event CostAuditResult.
- Build CostAuditOutput wrapper.
- Render: Table mode renders loading summary then aggregate table then per-event tables. JSON mode serializes CostAuditOutput.

**Step 4: Add [[bin]] entry to Cargo.toml:**
```toml
[[bin]]
name = "cost-audit"
path = "src/bin/cost_audit.rs"
```
Add after the existing match-audit bin entry.

IMPORTANT: CostBreakdown fields are Decimal with `#[serde(with = "rust_decimal::serde::str")]`. Convert to f64 using `.to_f64_lossy()` (from `rust_decimal::prelude::ToPrimitive` trait -- `use rust_decimal::prelude::*;`). Do NOT try to parse strings manually.

IMPORTANT: Do NOT double-normalize costs. The cost_breakdown values are already in probability space (per Phase 44 decision). Read them directly.
