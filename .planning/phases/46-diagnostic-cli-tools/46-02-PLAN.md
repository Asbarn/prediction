**Create src/analysis/book_depth.rs** with computation logic:

Define structs (all derive Debug, Clone, Serialize):

`InstrumentDepth`:
- `instrument_id: String`
- `venue: String` (prediction leg venue name)
- `signal_count: usize`
- `effective_spread_mean: f64` -- mean of (executable_price - probability) across signals for this instrument, converted from Decimal to f64
- `effective_spread_median: f64`
- `fill_ratio_mean: f64` -- mean fill_ratio for this instrument
- `fill_ratio_min: f64` -- worst fill ratio observed
- `depth_levels_mean: f64` -- mean book_depth_levels
- `depth_quality_score: f64` -- composite: `fill_ratio_mean * min(depth_levels_mean / 10.0, 1.0)` where 10 is the reference depth
- `estimated_max_fill: f64` -- `target_notional * fill_ratio_mean` where target_notional is passed as parameter (default 500.0)

`BookDepthResult`:
- `signal_count: usize`
- `instrument_count: usize`
- `effective_spread_mean: f64` -- aggregate across all signals
- `effective_spread_median: f64`
- `fill_ratio_mean: f64` -- aggregate
- `depth_levels_mean: f64` -- aggregate
- `depth_quality_score: f64` -- aggregate composite score
- `instruments: Vec<InstrumentDepth>` -- per-instrument breakdown, sorted by depth_quality_score ascending (worst first, so operator sees problem instruments first)

`BookDepthOutput`:
- `loading: LoadingSummary`
- `aggregate: BookDepthResult`
- `by_event: Option<BTreeMap<String, BookDepthResult>>`

Implement `pub fn compute_book_depth(signals: &[ArbSignal], target_notional: f64) -> BookDepthResult`:
- For each signal, extract from prediction_leg: effective_spread = (executable_price - probability).to_f64_lossy().abs(), fill_ratio = fill_ratio.to_f64_lossy(), depth_levels = book_depth_levels as f64. Use `rust_decimal::prelude::*` for ToPrimitive.
- Compute aggregate stats using analysis::stats helpers (mean_f64, median_f64 with sorted slices).
- Group by prediction_leg.instrument_id to build per-instrument InstrumentDepth entries.
- Sort instruments by depth_quality_score ascending.

Implement `pub fn book_depth_table(result: &BookDepthResult) -> Table`:
- Use `new_table(&["Metric", "Value"])`, set_numeric_columns for col 1.
- Section "=== AGGREGATE ===" with rows: Signal Count, Instrument Count, Effective Spread (Mean), Effective Spread (Median), Fill Ratio (Mean), Depth Levels (Mean), Depth Quality Score. Format f64 to 6 decimal places.
- Section "=== PER-INSTRUMENT (worst first) ===" -- switch to a second table with headers ["Instrument", "Signals", "Eff Spread", "Fill Ratio", "Depth Lvls", "Quality", "Est Max Fill"]. One row per instrument. Format to 4 decimal places.
- Return both tables: make the function return `Vec<(String, Table)>` (title + table pairs) following the spread_analytics pattern with `analysis_tables`.

Actually, for simpler rendering compatible with `render_output`, use the single-table approach: section headers within one table, with the per-instrument section using section_header rows then data rows formatted as "  {instrument_id}" indented. This matches how signal-scoring renders multiple sections in one table.

- `--log-dir: PathBuf` -- default "signal_logs"
- `--target-notional: f64` -- default 500.0, for fill simulation sizing. Help text: "Target notional for fill simulation (default: 500)"

`#[command(name = "book-depth")]` and `#[command(about = "Analyze order book depth and fill quality from signal logs")]`.

main():
- Parse CLI, create DateRange, load files via range.files_in_dir, load_jsonl::<ArbSignal>.
- Build LoadingSummary (count unique event_ids).
- Handle empty data gracefully.
- Compute aggregate via compute_book_depth(&result.records, cli.target_notional).
- If --by-event: group by event_id, compute per-event BookDepthResult.
- Build BookDepthOutput.
- Table mode: render loading summary, then for aggregate call book_depth_table and print each (title, table) pair. For by_event, print "=== Event: {id} ===" header then tables.
