  <action>
Push the signal_logs volume mount fix to master to trigger the GitLab CI/CD deploy pipeline. Then verify the deployment succeeded and feeds are active.

Steps:
1. Git add, commit, and push the docker-compose.yml and infra/cdk/lib/prediction-stack.ts changes to master
2. Wait for the GitLab CI/CD pipeline to complete (check with `git log --oneline -1` to confirm the push, then wait ~3-5 minutes for deploy)
3. Verify deployment health via SSM. CRITICAL: on Windows/Git Bash, prefix ALL SSM commands with `MSYS_NO_PATHCONV=1`:

```bash
MSYS_NO_PATHCONV=1 aws ssm send-command \
  --instance-ids "$(aws ec2 describe-instances --filters 'Name=tag:Name,Values=*Prediction*' 'Name=instance-state-name,Values=running' --query 'Reservations[0].Instances[0].InstanceId' --output text)" \
  --document-name "AWS-RunShellScript" \
  --parameters 'commands=["docker ps --format \"{{.Names}} {{.Status}}\""]' \
  --query "Command.CommandId" --output text
```

4. Check the command output with `aws ssm get-command-invocation` to confirm the prediction container is running and healthy
5. Check feed status via SSM: run `docker exec prediction-prediction-1 curl -sf http://localhost:9001/health` to confirm health endpoint responds
6. Check signal_logs directory exists on host: `ls -la /opt/prediction/data/signal_logs/`

If feeds are not running or health check fails, check container logs via SSM: `docker logs --tail 50 prediction-prediction-1`
