```rust
/// REST polling interval in seconds (how often to poll /midpoint when in REST mode).
#[serde(default = "default_rest_poll_interval")]
pub rest_poll_interval_secs: u64,

/// How often to attempt WS reconnection while in REST mode (seconds).
#[serde(default = "default_ws_recovery_check_secs")]
pub ws_recovery_check_secs: u64,

/// Number of WS messages needed to confirm WS is recovered before switching back.
#[serde(default = "default_ws_recovery_threshold")]
pub ws_recovery_threshold: u32,
```

Add default functions: `default_rest_poll_interval` -> 5, `default_ws_recovery_check_secs` -> 60, `default_ws_recovery_threshold` -> 3.

Update `src/config/validation.rs` and `tests/pipeline_test.rs` to add these three new fields (with default values) to ALL PolymarketConfig struct literals to prevent compilation errors.

**2. REST poller module** `src/feed/polymarket/rest_poller.rs`:

Create `PolymarketRestPoller` struct:
- Fields: `config: PolymarketConfig`, `client: reqwest::Client`, `rate_limiter: VenueRateLimiter`, `cancel: CancellationToken`, `health: Arc<VenueHealth>`
- Constructor: `new(config, client, rate_limiter, cancel, health) -> Self`

Create response type:
```rust
#[derive(Debug, serde::Deserialize)]
struct MidpointResponse {
    mid: String,
}
```

Implement `fetch_midpoint` method: GET `{rest_url}/midpoint?token_id={token_id}`, rate-limit via `rate_limiter.wait().await`, parse response, return `Decimal`.

Implement `run` method signature:
```rust
pub async fn run(
    self,
    assets: watch::Receiver<Vec<PolymarketSubscription>>,
    tx: mpsc::Sender<MarketSnapshot>,
)
```

The run loop:
1. Every `rest_poll_interval_secs`, read current assets from watch channel
2. For each asset token_id, call `fetch_midpoint`
3. Convert midpoint `Decimal` to `MarketSnapshot`:
   - `venue: Venue::Polymarket`
   - `instrument_id: InstrumentId::new(&token_id)`
   - `bid` and `ask` both set to `Price::new(midpoint)` (midpoint is best estimate)
   - `bid_probability` and `ask_probability` from `Probability::new(midpoint).ok()`
   - `depth_bids` and `depth_asks` empty (REST has no depth)
   - `is_stale: false`
   - `received_at: DualTimestamp::now()`
   - `sequence` incrementing counter (AtomicU64)
   - Other fields: None/default as appropriate
4. Send snapshot to `tx`
5. On first successful poll, call `health.mark_available()`
6. On error, log warning, increment `feed_rest_polls_total{venue=polymarket,status=error}` counter
7. On success, increment `feed_rest_polls_total{venue=polymarket,status=success}` counter
8. Record poll duration with `feed_rest_poll_duration_ms{venue=polymarket}` histogram
9. Respect cancellation token in the loop (tokio::select with cancel.cancelled())

IMPORTANT: Do NOT use `/book` endpoint (returns stale ghost data per GitHub #180). Use `/midpoint` only.
