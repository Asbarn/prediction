**SourceMode enum:**
```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum SourceMode {
    WebSocket,
    Rest,
}
```

**SourceCoordinator struct:**
```rust
pub struct SourceCoordinator {
    config: PolymarketConfig,
    assets_rx: watch::Receiver<Vec<PolymarketSubscription>>,
    cancel: CancellationToken,
    health: Arc<VenueHealth>,
    rate_limiter: VenueRateLimiter,
    http_client: reqwest::Client,
    recording_tx: Option<mpsc::Sender<RecordLine>>,
}
```

Constructor: `new(config, assets_rx, cancel, health, rate_limiter, http_client, recording_tx) -> Self`

**run method** signature:
```rust
pub async fn run(self, snapshot_tx: mpsc::Sender<MarketSnapshot>)
```

**State machine loop:**

The coordinator starts in WebSocket mode and runs a loop:

```
loop {
    match current_mode {
        SourceMode::WebSocket => {
            // 1. Create internal channels for WS supervisor -> processor -> snapshot
            // 2. Spawn PolymarketSupervisor with its own CancellationToken (child of self.cancel)
            // 3. Spawn PolymarketProcessor
            // 4. Forward snapshots from processor to snapshot_tx
            // 5. Monitor: wait for health.is_available() to become false
            //    (triggered by data_timeout or connection loss in supervisor)
            // 6. When health goes unavailable: cancel the child token (stops supervisor+processor),
            //    switch to SourceMode::Rest
            // 7. Emit metric: feed_source_mode gauge set to 1 (REST)
            // 8. Emit metric: feed_source_switches_total{from=ws, to=rest} increment
            // 9. Log: "Polymarket: switching from WebSocket to REST polling"
        }
        SourceMode::Rest => {
            // 1. Create child CancellationToken
            // 2. Spawn PolymarketRestPoller (from plan 01) with child token
            // 3. Forward REST-produced snapshots to snapshot_tx
            // 4. Emit metric: feed_source_mode gauge set to 1 (REST)
            // 5. After ws_recovery_check_secs, attempt WS probe:
            //    a. Create a temporary PolymarketClient, try connecting
            //    b. Wait for ws_recovery_threshold messages within data_timeout_secs
            //    c. If probe succeeds: cancel REST child token, switch to SourceMode::WebSocket
            //    d. If probe fails: stay in REST, try again after ws_recovery_check_secs
            // 6. On WS probe success:
            //    - Cancel REST poller child token
            //    - Set mode to WebSocket
            //    - Emit metric: feed_source_mode gauge set to 0 (WS)
            //    - Emit metric: feed_source_switches_total{from=rest, to=ws} increment
            //    - Log: "Polymarket: switching from REST to WebSocket (recovery confirmed)"
        }
    }
    // Check main cancel token at top of loop
    if self.cancel.is_cancelled() { break; }
}
```

**Critical design constraints (from research):**
- NEVER run WS and REST simultaneously sending to the same snapshot channel. Cancel old source FIRST, then start new.
- WS probe during REST mode should use a SEPARATE temporary channel, not the snapshot_tx. Only switch when probe confirms data flow.
- The health state (`VenueHealth`) should reflect the ACTIVE source's health, not the probe's.

**Forwarding pattern:** The coordinator needs to relay snapshots from the active source's channel to `snapshot_tx`. Use a simple forwarding loop within each mode arm, or pass `snapshot_tx.clone()` to the active source. Since the REST poller sends MarketSnapshot directly and the WS path goes through supervisor->processor->snapshot, the coordinator should:
- In WS mode: pipe processor output to snapshot_tx
- In REST mode: REST poller sends directly to snapshot_tx

The forwarding from processor to snapshot_tx does NOT go through `forward_snapshots()` -- that is done downstream in pipeline.rs. The coordinator produces raw venue snapshots.

Actually, review the pipeline code: the current pipeline has supervisor->processor->venue_snapshot_rx, then forward_snapshots pipes venue_snapshot_rx to fan_in_tx with event_id annotation. The coordinator should replace the supervisor+processor spawn, outputting on a channel that goes to forward_snapshots. So the coordinator's `snapshot_tx` is what currently would be `venue_snapshot_rx` writer side.

In WS mode: spawn supervisor, spawn processor, forward processor's output to `snapshot_tx`.
In REST mode: REST poller sends directly to `snapshot_tx`.

**Metrics:**
- `feed_source_mode{venue=polymarket}` gauge: 0 = WS, 1 = REST
- `feed_source_switches_total{venue=polymarket, from=ws/rest, to=rest/ws}` counter

Add `pub mod coordinator;` to `src/feed/polymarket/mod.rs`.
