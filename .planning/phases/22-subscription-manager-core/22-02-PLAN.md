Modify `src/main.rs` to create and wire the SubscriptionManager:

1. Add imports at the top:
   ```rust
   use tokio::sync::Notify;
   use prediction::subscription::SubscriptionManager;
   ```

2. **Create the Notify and watch channels** -- after `event_registry` is created but before the pipeline starts (in the `is_live` block, before `run_multi_venue_pipeline`):
   ```rust
   // Create subscription management infrastructure (live mode only)
   let registry_notify = Arc::new(Notify::new());
   let (sub_senders, sub_receivers) = {
       let reg = event_registry_clone.read().await;  // Use the appropriate registry Arc
       SubscriptionManager::create_channels(&reg)
   };
   ```
   Find where `event_registry` is created (as `Arc<RwLock<EventRegistry>>`) and place this code after it. Use the same Arc clone that the config reload subscriber uses.

3. **Modify the config reload subscriber** (currently lines ~286-318). After `reg.refresh(&new_config.events)` and `tracing::info!(...)`, add:
   ```rust
   drop(reg); // Release write lock before notifying
   registry_notify.notify_one(); // Wake SubscriptionManager for reconciliation
   ```
   The `drop(reg)` is CRITICAL -- if the write lock is held when Notify fires and SubscriptionManager tries to acquire a read lock, it will deadlock. Current code already drops `reg` implicitly at the end of the match arm, but an explicit `drop(reg)` before `notify_one()` makes the ordering guarantee visible and prevents future regressions.

   Clone `registry_notify` into the config reload subscriber's async block: `let config_notify = registry_notify.clone();`

4. **Spawn the SubscriptionManager** -- after the config reload subscriber is spawned, before the pipeline fan-out section:
   ```rust
   // Spawn SubscriptionManager for reconciliation on config changes
   let sub_manager = SubscriptionManager::new(
       event_registry.clone(),  // Same Arc<RwLock<EventRegistry>>
       registry_notify.clone(),
       shutdown_token.child_token(),
       sub_senders,
   );
   tokio::spawn(sub_manager.run());
   tracing::info!("SubscriptionManager started");
   ```

5. **Attach receivers to PipelineHandles** -- after `run_multi_venue_pipeline()` returns, set the subscription receivers:
   ```rust
   pipeline_handles.subscription_rx = Some(sub_receivers);
   ```
   This makes the receivers available for Phase 23 to extract and pass to supervisors.

6. **Guard for non-live modes**: All subscription management code (Notify, channels, SubscriptionManager) should only exist inside the `if is_live { ... }` block. In Mock/Replay modes, subscriptions are static and PipelineHandles.subscription_rx remains None.

**Ordering guarantee (SUB-04):**
The sequence is: `config_rx.changed()` fires -> `registry.refresh()` completes -> `drop(reg)` releases write lock -> `registry_notify.notify_one()` -> SubscriptionManager's `notified()` returns -> `reconcile()` acquires read lock and reads fresh state.

**Key constraints:**
- Do NOT modify any supervisor construction code -- Phase 23 handles that.
- Do NOT change the `run_live_multi_venue` function signature -- use the PipelineHandles field instead.
- The SubscriptionManager `new()` takes ownership of `SubscriptionSenders`. Receivers go to PipelineHandles.
- The `registry_notify` must be `Arc<Notify>` shared between the config reload subscriber and the SubscriptionManager.
