**src/subscription/manager.rs:**

1. Define `PolymarketSubscription` struct with `condition_id: String` and `token_id: String`. Derive `Debug, Clone, PartialEq, Eq, Hash`. This struct is needed because Polymarket subscriptions carry two IDs (condition_id for the market, token_id for the outcome), unlike Deribit/Kalshi which use a single string identifier.

2. Define `SubscriptionManager` struct with fields:
   - `registry: Arc<RwLock<EventRegistry>>` -- shared registry reference
   - `registry_notify: Arc<Notify>` -- wakeup signal from config reload
   - `cancel: CancellationToken` -- shutdown coordination
   - `deribit_tx: watch::Sender<Vec<String>>` -- Deribit instrument list channel
   - `polymarket_tx: watch::Sender<Vec<PolymarketSubscription>>` -- Polymarket subscription channel
   - `kalshi_tx: watch::Sender<Vec<String>>` -- Kalshi ticker channel
   - `current_deribit: HashSet<String>` -- current Deribit subscription state for diff
   - `current_polymarket: HashSet<PolymarketSubscription>` -- current Polymarket state
   - `current_kalshi: HashSet<String>` -- current Kalshi state

3. Implement `SubscriptionManager::new()` constructor that takes `registry`, `registry_notify`, `cancel`, and the three `watch::Sender` handles. Initialize `current_*` sets as empty -- the first reconciliation will populate them and send the initial state.

4. Implement `compute_desired_instruments(registry: &EventRegistry) -> (HashSet<String>, HashSet<PolymarketSubscription>, HashSet<String>)` as a private associated function. Iterates `registry.active_approved()` and collects:
   - Deribit: `mapping.venues.deribit.as_ref().map(|d| d.instrument.clone())` into HashSet
   - Polymarket: `mapping.venues.polymarket.as_ref().map(|p| PolymarketSubscription { condition_id: p.condition_id.clone(), token_id: p.token_id.clone() })` into HashSet
   - Kalshi: `mapping.venues.kalshi.as_ref().map(|k| k.ticker.clone())` into HashSet
   This function ONLY reads active_approved() mappings -- OPS-02 safety gate.

5. Implement generic `compute_diff<T: Clone + Eq + Hash>(current: &HashSet<T>, desired: &HashSet<T>) -> (Vec<T>, Vec<T>)` that returns `(added, removed)` using `HashSet::difference()`.

6. Implement `reconcile(&mut self)` async method:
   a. Acquire registry read lock: `let reg = self.registry.read().await;`
   b. Compute desired: `let (desired_d, desired_p, desired_k) = Self::compute_desired_instruments(&reg);`
   c. Drop the read lock immediately: `drop(reg);` -- CRITICAL to avoid holding lock during watch send (Pitfall 1 from research).
   d. Compute diffs for each venue using `compute_diff()`.
   e. Log each venue diff using structured tracing (see logging below).
   f. If any venue has a non-empty diff (added or removed is non-empty), send the new desired set via the venue's watch::Sender as a sorted Vec (sort for deterministic logging). Use `self.deribit_tx.send_replace(desired_d.into_iter().collect::<Vec<_>>())`. For Polymarket, sort by token_id.
   g. If ALL three venues have empty diffs, log at debug level: "subscription reconciliation: no changes across all venues".
   h. Update `self.current_*` sets to the new desired sets.

7. Structured tracing for diffs (OBS-03):
   - For each venue with changes: `tracing::info!(venue = %venue_name, added_count = added.len(), removed_count = removed.len(), total = desired.len(), added = ?added, removed = ?removed, "subscription reconciliation: diff computed")`
   - For each venue with no changes: `tracing::debug!(venue = %venue_name, total = current.len(), "subscription reconciliation: no changes")`

8. Implement `pub async fn run(mut self)`:
   ```rust
   loop {
       tokio::select! {
           biased;
           _ = self.cancel.cancelled() => {
               tracing::info!("SubscriptionManager shutting down");
               break;
           }
           _ = self.registry_notify.notified() => {
               self.reconcile().await;
           }
       }
   }
   ```

9. Implement a `pub fn create_channels(registry: &EventRegistry) -> (watch channels senders, watch channel receivers)` associated function that:
   - Calls `compute_desired_instruments(registry)` to get initial values
   - Creates three watch channels seeded with the initial instrument lists (converted to sorted Vecs)
   - Returns a struct or tuple containing the senders and receivers
   This avoids Pitfall 2 (empty initial value) by seeding with actual startup instruments.

   Define helper structs for clarity:
   ```rust
   pub struct SubscriptionSenders {
       pub deribit: watch::Sender<Vec<String>>,
       pub polymarket: watch::Sender<Vec<PolymarketSubscription>>,
       pub kalshi: watch::Sender<Vec<String>>,
   }
   pub struct SubscriptionReceivers {
       pub deribit: watch::Receiver<Vec<String>>,
       pub polymarket: watch::Receiver<Vec<PolymarketSubscription>>,
       pub kalshi: watch::Receiver<Vec<String>>,
   }
   ```
