a) **Install Docker** (AL2023 uses `dnf`):
```bash
dnf install -y docker
systemctl enable docker
systemctl start docker
```

b) **Install docker-compose v2 plugin**:
```bash
mkdir -p /usr/local/lib/docker/cli-plugins
curl -SL "https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64" \
  -o /usr/local/lib/docker/cli-plugins/docker-compose
chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
```

c) **Install jq** for secrets parsing:
```bash
dnf install -y jq
```

d) **Install and configure CloudWatch agent**:
```bash
dnf install -y amazon-cloudwatch-agent
```
Then write the CW agent config to `/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json` via heredoc in user-data. Start with:
```bash
/opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -a fetch-config -m ec2 -s -c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json
```

e) **Create fetch-secrets.sh** at `/opt/prediction/fetch-secrets.sh` via heredoc in user-data:
- Uses `set -euo pipefail`
- Reads from `prediction/prod/credentials` in `us-east-1`
- Uses `aws secretsmanager get-secret-value --query SecretString --output text`
- Pipes through jq to extract each key
- Writes `/opt/prediction/.env` with lines: `DERIBIT_API_KEY=...`, `DERIBIT_API_SECRET=...`, `POLYMARKET_PRIVATE_KEY=...`, `KALSHI_API_KEY_ID=...`, `KALSHI_PRIVATE_KEY=...`
- Uses `// empty` jq filter so missing keys produce empty values rather than "null"
- `chmod 600 /opt/prediction/.env`
- `chmod +x /opt/prediction/fetch-secrets.sh`
- Also runs ECR login: `aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 606103597377.dkr.ecr.us-east-1.amazonaws.com`

f) **Write docker-compose.yml** to `/opt/prediction/docker-compose.yml` via heredoc in user-data. Use the production compose config (see Task 2's docker-compose.yml content for the exact spec -- the user-data must write the same content). This ensures the EC2 instance always has the compose file without needing CI/CD for initial boot.

g) **Create systemd unit** at `/etc/systemd/system/prediction.service` via heredoc in user-data:
```ini
[Unit]
Description=Prediction Market Arbitrage System
After=docker.service network-online.target
Requires=docker.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/prediction
ExecStartPre=/opt/prediction/fetch-secrets.sh
ExecStart=/usr/bin/docker compose up --no-build
ExecStop=/usr/bin/docker compose down
Restart=on-failure
RestartSec=10
TimeoutStopSec=45
Environment=AWS_DEFAULT_REGION=us-east-1

[Install]
WantedBy=multi-user.target
```

h) **Enable and start the service**:
```bash
systemctl daemon-reload
systemctl enable prediction
systemctl start prediction
```

- Use `instance.userData.addCommands(...)` to append to existing user-data (do NOT replace the EBS volume commands)
- For multi-line heredocs in user-data, each line is a separate string argument to `addCommands()`
- The simplest approach for heredocs: write the JSON/script inline in user-data via `cat > /path <<'EOF'` style, with each line as a separate addCommands string argument

<task type="auto">
  <name>Task 2: Update docker-compose.yml for production deployment</name>
  <files>docker-compose.yml</files>
  <action>
Update the root `docker-compose.yml` to be production-ready for EC2 deployment:

1. **Add `stop_grace_period: 30s`** to the prediction service (HARD-03). This gives the Rust app time to flush checkpoints, close WebSocket connections, and exit cleanly before Docker sends SIGKILL. The default 10s is too short.

2. **Add `env_file: .env`** to explicitly load the `.env` file generated by fetch-secrets.sh (HARD-01). Remove the existing `environment: []` line.

3. **Update volume paths** to use the EC2 data volume mount structure:
```yaml
volumes:
  - /opt/prediction/data/config:/app/config
  - /opt/prediction/data/spread_logs:/app/spread_logs
  - /opt/prediction/data/settlement_logs:/app/settlement_logs
  - /opt/prediction/data/paper_trades:/app/paper_trades
  - /opt/prediction/data/state:/app/state
  - /opt/prediction/data/logs:/app/logs
```
Note: Remove the `./secrets:/app/secrets:ro` volume -- secrets are now injected via environment variables from Secrets Manager, not mounted files.

4. **Keep existing settings unchanged**: ports (9000, 9001), healthcheck, image URI. Change `restart: unless-stopped` to `restart: "no"` since systemd manages restart policy (having both systemd Restart=on-failure and docker restart=unless-stopped creates confusing double-restart behavior).

5. **Keep the logging driver as json-file** for now. Phase 36 will change it to awslogs.

The final docker-compose.yml should look like:
```yaml
services:
  prediction:
    image: 606103597377.dkr.ecr.us-east-1.amazonaws.com/prediction:latest
    env_file: .env
    stop_grace_period: 30s
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - /opt/prediction/data/config:/app/config
      - /opt/prediction/data/spread_logs:/app/spread_logs
      - /opt/prediction/data/settlement_logs:/app/settlement_logs
      - /opt/prediction/data/paper_trades:/app/paper_trades
      - /opt/prediction/data/state:/app/state
      - /opt/prediction/data/logs:/app/logs
    logging:
      driver: json-file
      options:
        max-size: "50m"
        max-file: "3"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9001/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 15s
    restart: "no"
```
