  <files>

  </files>
  <action>
Create an integration test that connects to the Derive WebSocket API and captures messages. This test is `#[ignore]` by default (requires network) but runnable on demand.

The test should:

1. **Connect** to `wss://api.lyra.finance/ws` (production) OR `wss://api-demo.lyra.finance/ws` (testnet) using `tokio-tungstenite`. Try testnet first; fall back to production if testnet is unreachable.

2. **Test unauthenticated subscribe** -- Send a JSON-RPC subscribe request without prior authentication:
   ```json
   {
     "jsonrpc": "2.0",
     "id": 1,
     "method": "subscribe",
     "params": {"channels": ["orderbook.BTC-20250627-100000-C"]}
   }
   ```
   If this returns an error, try alternative channel name formats:
   - `orderbook.{instrument_name}.raw`
   - `book.{instrument_name}`
   - `{instrument_name}.book`
   Also try the ticker channel:
   ```json
   {
     "jsonrpc": "2.0",
     "id": 2,
     "method": "subscribe",
     "params": {"channels": ["ticker.BTC-20250627-100000-C"]}
   }
   ```

3. **Capture 20+ messages** after successful subscribe. Write each raw JSON message to stdout with a sequence number. Collect for at least 30 seconds or until 20+ messages received.

4. **Test authentication requirement** -- If unauthenticated subscribe fails with an auth error, document that authentication IS required for public channels (this would mean k256 dependency is needed in Phase 31).

5. **Detect heartbeat mechanism** -- During the capture window, observe if the server sends periodic ping frames (WS-level) or custom heartbeat messages (application-level JSON-RPC notifications). Log any ping/pong activity.

6. **Detect book model** -- From captured orderbook messages, determine:
   - Does the first message contain a full snapshot (all bids/asks)?
   - Do subsequent messages contain full snapshots or incremental deltas?
   - What fields are present in each message? (bids, asks, timestamp, sequence, type/action)

Structure the test as:
```rust
#[cfg(test)]
mod derive_api_probe {
    use tokio_tungstenite::connect_async;
    use futures_util::{SinkExt, StreamExt};

    #[tokio::test]
    #[ignore] // Requires network access to Derive API
    async fn probe_derive_websocket() {
        // ... connection and message capture
    }
}
```

After creating the test, run it:
```bash
cargo test --test derive_api_probe probe_derive_websocket -- --ignored --nocapture 2>&1 | tee /tmp/derive_probe_output.txt
```

If the test cannot connect (network blocked, DNS failure), try using `curl` or `websocat` as alternatives:
```bash
# Alternative: use curl to test REST endpoint first
curl -s -X POST https://api.lyra.finance/public/get_instruments -H "Content-Type: application/json" -d '{"instrument_type": "option", "currency": "BTC"}' | head -c 2000
```

**Important:** If network access to Derive API is completely blocked from this machine, document that finding and skip to Task 2 with findings from the research document's secondary sources (CCXT, Hummingbot, official docs) as best-available evidence.
