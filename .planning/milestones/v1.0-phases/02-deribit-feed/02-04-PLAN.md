    **3. Create `src/feed/mock/replay.rs` -- ReplayDataSource:**
    Reads a JSONL recording file and produces `RawMessage` items through an mpsc channel at configurable speed.

    ```rust
    pub struct ReplayDataSource {
        file_path: PathBuf,
        speed: f64,  // 0.0 = instant, 1.0 = real-time, 10.0 = 10x fast-forward
    }
    ```

    Methods:
    - `new(file_path: PathBuf, speed: f64) -> Self`
    - `start(self, cancel: CancellationToken) -> Result<mpsc::Receiver<RawMessage>, anyhow::Error>`:
      1. Open the JSONL file and read all lines into memory (or use async line reader for large files)
      2. Parse each line as `RecordLine` to extract `raw` text and `local_ts`
      3. Spawn a tokio task that iterates through the parsed lines:
         - If `speed > 0.0`: compute the time delta between consecutive `local_ts` values. Sleep for `delta / speed` between sends. This preserves realistic timing at 1x, accelerates at 10x, and runs instantly at 0.
         - If `speed == 0.0`: send all messages as fast as possible (no sleep)
         - For each line, create a `RawMessage { text: line.raw, received_at: DualTimestamp::now() }`
         - Send through the mpsc channel (buffer 1024)
         - Respect CancellationToken via `tokio::select!`
         - When all lines are exhausted, log "replay complete" and drop the sender (receiver gets None)
      4. Return the receiver

    Implement the `RawDataSource` trait for `ReplayDataSource`.

    **4. Create `src/feed/mock/synthetic.rs` -- SyntheticDataSource:**
    Generates realistic Deribit-format JSON-RPC messages without needing any recorded data.

    ```rust
    pub struct SyntheticDataSource {
        instruments: Vec<String>,
        interval_ms: u64,      // How often to generate snapshots (default 100ms matching grouped channel)
        base_price: f64,       // Starting BTC price (default ~95000)
        spread_bps: f64,       // Spread in basis points (default 10)
        depth_levels: usize,   // Number of book levels (default 20)
    }
    ```

    Methods:
    - `new(instruments: Vec<String>) -> Self` with sensible defaults
    - `with_interval(mut self, ms: u64) -> Self` -- builder pattern
    - `with_base_price(mut self, price: f64) -> Self`
    - `start(self, cancel: CancellationToken) -> mpsc::Receiver<RawMessage>`:
      1. Spawn a tokio task that generates messages in a loop:
         - For each instrument, every `interval_ms`:
           - Generate a `BookData`-shaped JSON string with realistic top-20 levels. Use `rand` to add small random walk to prices. Wrap in the Deribit notification envelope: `{"jsonrpc":"2.0","method":"subscription","params":{"channel":"book.{inst}.none.20.100ms","data":{...}}}`
           - Generate a `TickerData`-shaped JSON string with mark_price, index_price, and synthetic greeks. Wrap in notification envelope.
           - Occasionally (every ~10 intervals): generate a `TradeData` array notification.
           - Include `change_id` and `prev_change_id` that increment correctly to avoid sequence gap errors.
         - Send each as `RawMessage { text: json_string, received_at: DualTimestamp::now() }`
         - Sleep for `interval_ms` between rounds
         - Respect CancellationToken
      2. Return the receiver

    Implement the `RawDataSource` trait for `SyntheticDataSource`.

    The synthetic generator does NOT need to be perfectly realistic -- it needs to produce valid JSON that the parser and book manager can process without errors. The goal is enabling development without live data or recordings.

    The pipeline assembly function wires all components together based on the selected mode.

    Define a `DataMode` enum:
    ```rust
    pub enum DataMode {
        Live,                              // Connect to real Deribit WS
        Replay { path: PathBuf, speed: f64 }, // Replay from JSONL file
        Mock,                              // Synthetic data generation
    }
    ```

    Implement `run_pipeline`:
    ```rust
    pub async fn run_pipeline(
        mode: DataMode,
        config: &VenuesConfig,
        recording_dir: PathBuf,
        cancel: CancellationToken,
    ) -> anyhow::Result<mpsc::Receiver<MarketSnapshot>> {
    ```

    This function:
    1. Creates the downstream snapshot channel: `mpsc::channel::<MarketSnapshot>(256)` (per research)
    2. Creates the `RecordingService` for the venue (Deribit) pointing at `recording_dir`
    3. Based on `mode`:
       - `Live`: Create `DeribitClient` with instruments from config, call `start()` to get `Receiver<RawMessage>`
       - `Replay { path, speed }`: Create `ReplayDataSource`, call `start()` to get `Receiver<RawMessage>`
       - `Mock`: Create `SyntheticDataSource` with instruments from config, call `start()` to get `Receiver<RawMessage>`
    4. Creates `DeribitProcessor` with the raw message receiver, snapshot sender, recording sender, and CancellationToken
    5. Spawns the processor task via `tokio::spawn(processor.run())`
    6. Returns the `Receiver<MarketSnapshot>` for downstream consumers (will be consumed by spread calculator in Phase 6)

    For Phase 2, the downstream consumer is a simple logging task that prints received snapshots at info level to prove the pipeline works end-to-end.
