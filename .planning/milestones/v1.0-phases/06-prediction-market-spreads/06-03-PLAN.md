**src/spread/engine.rs:** Implement the core spread computation engine:

- `pub struct SpreadEngine` -- not a background task itself (main.rs will consume the channel), but a stateful computation context:
  - `latest: HashMap<(String, Venue), MarketSnapshot>` -- latest snapshot per (event_id, venue)
  - `stats: HashMap<String, RollingStats>` -- rolling stats per event_id
  - `config: SpreadConfig`
  - `logger: SpreadLogger`
  - `signal_count: u64` (for metrics)

- `SpreadEngine::new(config: SpreadConfig) -> Self`

- `pub async fn run(mut self, mut snapshot_rx: mpsc::Receiver<MarketSnapshot>, registry: Arc<RwLock<EventRegistry>>, cancel: CancellationToken, signal_tx: mpsc::Sender<SpreadResult>)`:
  - Main event loop using `tokio::select!` with biased selection:
    1. `cancel.cancelled()` -> break
    2. `stats_interval.tick()` -> call `self.emit_aggregate_stats()`
    3. `snapshot_rx.recv()` -> process snapshot
  - Stats interval: `tokio::time::interval(Duration::from_secs(config.stats_emission_interval_secs))`

- Snapshot processing logic (private method `process_snapshot`):
  1. Acquire read lock on EventRegistry
  2. Look up event mapping via `registry.lookup_by_instrument(snap.venue, &snap.instrument_id.to_string())`
  3. If no mapping found, continue (unmapped instrument)
  4. Only process if mapping has both Polymarket AND Kalshi venue entries (skip Deribit-only events, those are Phase 8)
  5. Update `self.latest` with the new snapshot keyed by (event_id, venue)
  6. Try to get both snapshots: `self.latest.get(&(event_id, Venue::Polymarket))` and `self.latest.get(&(event_id, Venue::Kalshi))`
  7. If both exist, proceed to staleness gate

- **Staleness gate** (SGNL-03):
  1. Check `poly.is_stale` and `kalshi.is_stale` flags
  2. Additionally check exchange_timestamp age: for Polymarket, `now_ms - exchange_timestamp > staleness_threshold_ms`. For Kalshi (which lacks exchange timestamps), check `now_ms - timestamp.wall_ms > kalshi_staleness_threshold_ms` (use a more permissive threshold, e.g., 15s vs 5s, since Kalshi is REST-polled)
  3. If either side fails staleness gate: log rejection with `tracing::debug!` (event_id, stale_venue, reason), increment `metrics::counter!("spread_staleness_rejections", "event" => event_id, "venue" => stale_venue)`, skip this event pair
  4. Use configurable staleness thresholds from SpreadConfig (add `staleness_threshold_ms: u64` and `kalshi_staleness_threshold_ms: u64` to SpreadConfig if not already present)

- **4-pattern spread computation** (SGNL-04 + SGNL-02):
  For each `pattern in SpreadPattern::all()`:
  1. Compute gross spread via `compute_gross_spread(pattern, &poly, &kalshi)` -- skip if None (missing probabilities)
  2. Determine which depth sides to walk per pattern:
     - Pattern 1 (Buy Poly YES, Sell Kalshi YES): buy walks poly.depth_asks, sell walks kalshi.depth_bids
     - Pattern 2 (Sell Poly YES, Buy Kalshi YES): buy walks kalshi.depth_asks, sell walks poly.depth_bids
     - Pattern 3 (Buy Poly NO, Sell Kalshi NO): buy walks poly.depth_bids (NO side = inverse), sell walks kalshi.depth_asks
     - Pattern 4 (Sell Poly NO, Buy Kalshi NO): buy walks kalshi.depth_bids, sell walks poly.depth_asks
  3. Walk the book on both sides: `walk_the_book(&buy_depth, config.target_notional)` and `walk_the_book(&sell_depth, config.target_notional)`
  4. Compute fees: `polymarket_fee(notional, fill_price, &config.polymarket_fees)` for the Poly side, `kalshi_taker_fee(contracts, fill_price, &config.kalshi_fees)` for the Kalshi side. Determine which venue is buy vs sell from the pattern.
  5. Compute carry cost: `carry_cost(config.target_notional, &config.carry)`
  6. Total cost = buy_fee + sell_fee + carry_cost
  7. Net spread = gross_spread - total_cost (adjusted for fill prices from walk-the-book rather than top-of-book)
     More precisely: net_spread = sell_fill_price - buy_fill_price - total_cost (where fill prices are the walked-the-book averages)
  8. Build `SpreadResult` with all fields populated including timestamp_ms, exchange timestamps from both snapshots

- **JSONL logging** (SGNL-07): Call `self.logger.log(&result).await` for EVERY spread computation (not just above-threshold ones).

- **Rolling stats update** (SGNL-08): Update per-event RollingStats with `net_spread.to_f64()`.

- **Threshold check**: Call `compute_threshold(stats, &config.threshold, &result)`. If net_spread > threshold, send result to `signal_tx` channel for paper trade tracker (Plan 04). Always emit to Prometheus histogram regardless: `metrics::histogram!("spread_net", "event" => event_id, "pattern" => pattern.label()).record(net_spread_f64)`.

- **Metrics emission on every computation**:
  - `metrics::histogram!("spread_net", "event" => event_id.clone(), "pattern" => pattern.label()).record(net_spread_f64)`
  - `metrics::counter!("spread_computations_total", "event" => event_id.clone()).increment(1)`
  - On threshold crossing: `metrics::counter!("spread_signals_total", "event" => event_id.clone(), "pattern" => pattern.label()).increment(1)`

- `fn emit_aggregate_stats(&self)`: For each event_id in self.stats:
  - Log to stdout via `tracing::info!` with event_id, count, mean, stddev, p50, p95
  - Emit to Prometheus gauges: `metrics::gauge!("spread_rolling_mean", "event" => event_id).set(mean)`, similarly for stddev

**src/spread/threshold.rs:** Implement the user-specified threshold formula:

- `pub fn compute_threshold(stats: &RollingStats, config: &ThresholdConfig, result: &SpreadResult) -> (Decimal, ThresholdComponents)`:
  Returns both the final threshold value AND the components struct for logging.

  Logic (per user decision in CONTEXT.md):
  1. Static floor from `config.static_floor`
  2. Dynamic component:
     - If `stats.count() >= config.min_samples_for_dynamic` (from ThresholdConfig, add field if needed):
       - `mean = Decimal::from_f64_retain(stats.mean()).unwrap_or(Decimal::ZERO)`
       - `stddev = Decimal::from_f64_retain(stats.stddev()).unwrap_or(Decimal::ZERO)`
       - `dynamic = mean + config.k * stddev`
     - Else (cold start): `dynamic = static_floor * config.cold_start_multiplier`
  3. Base = `max(static_floor, dynamic)`
  4. Liquidity penalty:
     - Compute fill_ratio from SpreadResult (average of buy and sell fill ratios)
     - If fill_ratio >= 1.0: penalty = 0
     - Else: `penalty = config.liquidity_penalty_scale * (1 - fill_ratio)`
  5. Final threshold = base + liquidity_penalty
  6. Build ThresholdComponents with all intermediate values including `is_cold_start: stats.count() < min_samples`

- Per user decision: "Log all threshold components (static floor, rolling mean, rolling stddev, k*sigma, liquidity penalty, final threshold) for post-hoc evaluation of which factor drives useful signals." -- The ThresholdComponents struct (defined in patterns.rs) captures all of these.

- Per user decision: "No cooldown or deduplication -- fire every threshold crossing, deduplication is a downstream concern."

- Per user decision: "Start with single window; design allows adding multiple windows (1h/4h/24h) later." -- The RollingStats already takes window_duration_secs, so adding multiple windows later means adding multiple RollingStats per event_id and choosing the appropriate one.

Unit tests:
- Cold start (0 samples): threshold = static_floor * cold_start_multiplier + liquidity_penalty
- Warm state (>min_samples): threshold = max(floor, mean + k * stddev) + liquidity_penalty
- Full fill (ratio=1.0): zero liquidity penalty
- Partial fill (ratio=0.5): liquidity_penalty = scale * 0.5
- Empty book (ratio=0): maximum liquidity penalty = scale * 1.0
- Edge case: mean + k*stddev < static_floor -> static_floor wins
