**src/spread/patterns.rs:** Define the 4-pattern spread detection types:

- `pub enum SpreadPattern` with 4 variants:
  1. `BuyPolyYesSellKalshiYes` -- Buy Polymarket YES (at ask), Sell Kalshi YES (at bid)
  2. `SellPolyYesBuyKalshiYes` -- Sell Polymarket YES (at bid), Buy Kalshi YES (at ask)
  3. `BuyPolyNoSellKalshiNo` -- Complement of pattern 2: buy Poly NO = sell Poly YES complement
  4. `SellPolyNoBuyKalshiNo` -- Complement of pattern 1: sell Poly NO = buy Poly YES complement
  - Derive `Debug, Clone, Copy, PartialEq, Eq, Serialize`
  - `SpreadPattern::all() -> [SpreadPattern; 4]` returns all 4 variants
  - `SpreadPattern::label(&self) -> &'static str` returns human-readable label (e.g., "buy_poly_yes_sell_kalshi_yes")
  - `SpreadPattern::buy_venue(&self) -> Venue` and `sell_venue(&self) -> Venue` for signal metadata

- `pub fn compute_gross_spread(pattern: SpreadPattern, poly: &MarketSnapshot, kalshi: &MarketSnapshot) -> Option<GrossSpread>`:
  - For pattern 1: spread = kalshi_bid_prob - poly_ask_prob (buy Poly at ask, sell Kalshi at bid)
  - For pattern 2: spread = poly_bid_prob - kalshi_ask_prob
  - For pattern 3: spread = (1 - poly_ask_prob) - (1 - kalshi_bid_prob) = kalshi_bid_prob - poly_ask_prob (algebraically same as pattern 1 BUT walk-the-book uses different depth sides)
  - For pattern 4: spread = (1 - kalshi_ask_prob) - (1 - poly_bid_prob) = poly_bid_prob - kalshi_ask_prob (algebraically same as pattern 2 BUT walk-the-book uses different depth sides)
  - Returns None if either snapshot lacks bid_probability or ask_probability
  - Uses Probability::complement() for NO side computation

- `pub struct GrossSpread`: `pattern: SpreadPattern`, `gross_spread: Decimal`, `buy_price: Decimal` (the probability paid), `sell_price: Decimal` (the probability received), `buy_venue: Venue`, `sell_venue: Venue`

- `pub struct SpreadResult` (serializable, for logging): `event_id: String`, `pattern: SpreadPattern`, `gross_spread: Decimal`, `net_spread: Decimal`, `buy_fill_price: Decimal`, `sell_fill_price: Decimal`, `buy_fee: Decimal`, `sell_fee: Decimal`, `carry_cost: Decimal`, `total_cost: Decimal`, `buy_fill_ratio: Decimal`, `sell_fill_ratio: Decimal`, `target_notional: Decimal`, `timestamp_ms: i64`, `poly_exchange_ts: Option<i64>`, `kalshi_exchange_ts: Option<i64>`, `threshold: Option<Decimal>`, `threshold_components: Option<ThresholdComponents>`
  - Derive `Debug, Clone, Serialize`

- `pub struct ThresholdComponents` (for logging threshold decision): `static_floor: Decimal`, `rolling_mean: f64`, `rolling_stddev: f64`, `k_sigma: f64`, `liquidity_penalty: Decimal`, `final_threshold: Decimal`, `is_cold_start: bool`
  - Derive `Debug, Clone, Serialize`

- Unit tests: verify all 4 patterns produce correct gross spread for known probabilities. Example: Poly ask_prob=0.45, Kalshi bid_prob=0.50 -> pattern 1 gross = 0.05. Verify None returned when probabilities missing. Verify pattern labels are distinct.

**src/spread/mod.rs:** Add `pub mod patterns;` to module declarations.

NOTE: Patterns 3 and 4 are algebraically equivalent to 1 and 2 in GROSS spread, but they are computed independently because the walk-the-book step (in Plan 03) will use different depth sides (asks vs bids) resulting in different NET spreads. The gross computation here is the first step; Plan 03's engine will apply the full cost model including walk-the-book to each pattern independently.
