    **Create src/events/registry.rs -- In-memory EventRegistry:**

    ```rust
    use std::collections::HashMap;
    use crate::config::{EventMapping, EventsConfig, LifecycleStatus, Direction};
    use crate::types::{EventId, InstrumentId, Venue};
    ```

    Implement `EventRegistry` struct with:
    - `mappings: Vec<EventMapping>` -- all mappings
    - `instrument_index: HashMap<(Venue, String), usize>` -- (Venue, instrument_id_string) -> index into mappings
    - `event_index: HashMap<String, Vec<usize>>` -- event_id -> indices (multiple venues per event is one mapping, but future-proofing)

    Methods:
    - `pub fn from_config(config: &EventsConfig) -> Self` -- builds both indexes by iterating mappings; for each mapping, index each venue's instrument:
      - deribit instrument -> (Venue::Deribit, instrument_name) -> idx
      - polymarket token_id -> (Venue::Polymarket, token_id) -> idx
      - kalshi ticker -> (Venue::Kalshi, ticker) -> idx
    - `pub fn lookup_by_instrument(&self, venue: Venue, instrument_id: &str) -> Option<&EventMapping>` -- O(1) lookup via instrument_index
    - `pub fn lookup_by_event_id(&self, event_id: &str) -> Option<&EventMapping>` -- O(1) lookup via event_index (return first match)
    - `pub fn active_approved(&self) -> impl Iterator<Item = &EventMapping>` -- filter for approved == true AND status == LifecycleStatus::Active
    - `pub fn all_mappings(&self) -> &[EventMapping]` -- return full slice
    - `pub fn refresh(&mut self, config: &EventsConfig)` -- rebuild from updated config (clear + rebuild indexes)
    - `pub fn mapping_count(&self) -> usize`
    - `pub fn active_count(&self) -> usize` -- count of active approved

    Add comprehensive unit tests:
    - Test from_config with empty config
    - Test lookup_by_instrument for each venue type (Deribit, Polymarket, Kalshi)
    - Test lookup_by_event_id
    - Test active_approved filters out expired and unapproved
    - Test refresh rebuilds indexes correctly
    - Test missing venue mapping returns None

    **Create src/events/toml_writer.rs -- Format-preserving TOML append:**

    ```rust
    use toml_edit::{DocumentMut, value, Table, ArrayOfTables};
    ```

    Implement:
    - `pub fn append_candidate_to_toml(existing_content: &str, candidate: &CandidateMapping) -> anyhow::Result<String>`
      - Parse existing content into `DocumentMut`
      - Get or create `[[events]]` array of tables
      - Build new table entry with: id, asset, strike, direction, expiry, approved=false, status="active", discovered_at=current RFC3339 timestamp
      - Add venue sub-tables based on which venues the candidate has
      - Append to the array
      - Return the modified document as string

    - Define `CandidateMapping` struct (input to the writer):
      ```rust
      pub struct CandidateMapping {

      pub struct CandidateVenues {

      }
      ```

    - `pub fn mark_expired_in_toml(existing_content: &str, event_id: &str) -> anyhow::Result<String>`
      - Parse into DocumentMut, find matching event entry, set status = "expired"

    Add unit tests:

    - Test append adds new entry with approved=false
    - Test mark_expired changes status field
    - Test error on missing [[events]] array
