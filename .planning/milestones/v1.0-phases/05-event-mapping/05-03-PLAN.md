       ```rust
       pub async fn discover_deribit(

           base_url: &str,     // e.g., "https://www.deribit.com"
           currencies: &[String],
       ) -> anyhow::Result<Vec<DiscoveredInstrument>>
       ```
       - GET `{base_url}/api/v2/public/get_instruments?currency={currency}&kind=option` for each currency
       - Parse `DeribitInstrumentsResponse { result: Vec<DeribitInstrumentInfo> }`

       - Filter for is_active, map option_type "call" -> Direction::Above, "put" -> Direction::Below
       - Convert strike f64 to Decimal via `Decimal::from_f64_retain`
       - Convert expiration_timestamp millis to NaiveDate via `DateTime::from_timestamp_millis`
       - Use the structured API response fields, NOT string parsing of instrument_name (per research "Don't Hand-Roll")

    **run() method -- main loop:**
    ```rust
    pub async fn run(self) {
        // Use the minimum poll interval across venues for the tick interval
        // (individual venue discovery runs only when their own interval has elapsed)
        let min_interval = self.discovery_config.min_poll_interval_secs();
        let mut interval = tokio::time::interval(Duration::from_secs(min_interval));
        let mut last_deribit_poll = Instant::now();
        let mut last_kalshi_poll = Instant::now();
        let mut last_polymarket_poll = Instant::now();

        loop {
            tokio::select! {
                biased;
                _ = self.cancel.cancelled() => {
                    tracing::info!("ContractLifecycleManager shutting down");
                    break;
                }
                _ = interval.tick() => {
                    self.poll_cycle(
                        &mut last_deribit_poll,
                        &mut last_kalshi_poll,
                        &mut last_polymarket_poll,
                    ).await;
                }
            }
        }
    }
    ```

    **poll_cycle() method:**
    1. **Discover instruments from each venue** (only if that venue's interval has elapsed):
       - Deribit: call `discover_deribit()` with configured currencies
       - Kalshi: call `discover_kalshi()` if credentials available (graceful skip if missing, like Phase 4 pattern)
       - Polymarket: call `discover_polymarket()` for deactivation monitoring
       - Log errors but continue (one venue failure doesn't stop others)
       - Emit `metrics::counter!("lifecycle_discovery_polls")` on each poll

    2. **Find new cross-venue candidates:**
       - Combine Deribit + Kalshi discovered instruments
       - Call `find_cross_venue_candidates()` and `filter_new_candidates()`
       - For each new candidate:
         - Append to events.toml via `append_candidate_to_toml()`
         - Log structured: `tracing::info!(event_id = %candidate.id, venues = ?candidate.venues, "discovered new candidate mapping")`
         - Emit `metrics::counter!("lifecycle_candidates_discovered")`

    3. **Flag novel/unmatched instruments:**
       - Call `flag_novel_instruments()` for each venue's discovered list
       - Log each: `tracing::info!(venue = %inst.venue, instrument = %inst.instrument_id, asset = %inst.asset, "novel unmatched instrument discovered")`

    4. **Detect expired instruments:**
       - Compare existing registry mappings against discovered instrument lists
       - If a mapped instrument is no longer active in the venue's API response -> mark as expired
       - Call `mark_expired_in_toml()` to archive
       - Log: `tracing::warn!(event_id = %mapping.id, "mapping expired")`

    5. **Handle Deribit expiry rolls:**
       - For each expired Deribit mapping, search discovered instruments for same asset + strike + direction but later expiry
       - If found, create new candidate with `approved = false` (per user decision -- approval does NOT carry over)
       - Append to events.toml, log

    6. **Apply expiry warnings to near-expiry active mappings:**
       - For each active approved mapping, compute hours to expiry
       - Call `check_expiry_warning()` with configured thresholds
       - If warning returned, log with tier: `tracing::warn!(event_id = %id, tier = %warning.tier_name, flags = ?warning.flags, hours = %warning.hours_to_expiry, "near-expiry warning")`
       - Emit `metrics::gauge!("lifecycle_expiry_warnings")` with count

    7. **Refresh runtime registry:**
       - Read updated events.toml from disk
       - Parse to EventsConfig
       - Call `registry.write().await.refresh(&config)`

    **File I/O safety:**
    - Read events.toml content before modifying
    - Write to a temporary file (events.toml.tmp) then rename atomically (per research pitfall 4)
    - Use a Mutex or sequential execution in poll_cycle to prevent concurrent writes (per research pitfall 7)
    - The lifecycle manager is the sole writer to events.toml (config reloader only reads)

    **Wire into main.rs:**
    - In Live mode (after multi-venue pipeline starts), create and spawn ContractLifecycleManager:
      - Create `Arc<RwLock<EventRegistry>>` from loaded EventsConfig
      - Pass events_toml_path as `config_dir.join("events.toml")`
      - Pass discovery/expiry/risk configs from AppConfig
      - Pass VenuesConfig and Credentials
      - Pass child CancellationToken (like the per-venue pattern from Phase 4)
      - `tokio::spawn(lifecycle_manager.run())`
    - Log at startup: `tracing::info!("ContractLifecycleManager started")`
    - In Mock/Replay modes, do NOT start lifecycle manager (no REST polling)

    **Update src/feed/pipeline.rs:**
    - Accept `Arc<RwLock<EventRegistry>>` parameter in `run_multi_venue_pipeline()` (pass-through for now; Phase 6 will use it for snapshot annotation)
    - This is a minimal interface change to thread the registry through

    - Test expiry warning application: mapping within 24h -> "warning" tier
    - Test registry refresh after TOML modification
    - Test graceful handling when Kalshi credentials missing (no crash, skip Kalshi discovery)
