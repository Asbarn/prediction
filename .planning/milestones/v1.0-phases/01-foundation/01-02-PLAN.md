  <action>
    1. **Update src/lib.rs** to add `pub mod logging;`

    2. **Create src/logging/mod.rs**:
       - Re-export: `pub use layers::init_logging;`
       - Declare submodule: `mod layers;`

    3. **Create src/logging/layers.rs** implementing dual-output logging:
       - `init_logging(log_dir: &str, stdout_level: &str, file_level: &str) -> anyhow::Result<tracing_appender::non_blocking::WorkerGuard>`:

       - **Stdout layer** (human-readable):
         - Use `tracing_subscriber::fmt::layer()` with `.with_target(true)` and `.with_level(true)`
         - Apply per-layer `EnvFilter` constructed from `stdout_level` parameter
         - Default filter: "prediction=info" (only show INFO+ from our crate)
         - This layer shows signals, errors, and connection state changes to the operator

       - **File layer** (structured JSON):
         - Create rolling daily appender: `tracing_appender::rolling::daily(log_dir, "prediction.log")`
         - Wrap in non-blocking writer: `tracing_appender::non_blocking(file_appender)` -- returns (writer, guard)
         - Use `tracing_subscriber::fmt::layer().json()` with `.with_writer(non_blocking_writer)`
         - Enable `.with_current_span(true)` and `.with_span_list(true)` for full span context
         - Apply per-layer `EnvFilter` constructed from `file_level` parameter
         - Default filter: "prediction=debug" (capture everything from our crate)

       - **Compose with Registry** (per-layer filtering -- NOT global filter):
         ```rust
         use tracing_subscriber::{prelude::*, Registry};

         Registry::default()
             .with(stdout_layer.with_filter(stdout_filter))
             .with(file_layer.with_filter(file_filter))
             .init();
         ```

       - **Return the WorkerGuard** -- caller (main.rs) MUST hold this alive for the entire program lifetime. If dropped, buffered log entries are lost. This is the #1 pitfall from research.

       - Create the log directory if it doesn't exist: `std::fs::create_dir_all(log_dir)?`

       - Handle `EnvFilter::try_new()` errors gracefully -- if the filter string is invalid, return an error instead of panicking.

    See research Pattern 1 (Dual-Output Tracing) and Pitfall 1 (WorkerGuard) and Pitfall 2 (Incorrect Per-Layer Filter Setup) for critical details.

    Do NOT use global `EnvFilter` (applies same filter to both layers -- wrong).
    Do NOT drop or ignore the WorkerGuard.
    Do NOT use `unwrap()` in non-test code.
  </action>
