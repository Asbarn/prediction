  <name>Task 1: PricingEngine struct with per-expiry state management and ImpliedProbability emission</name>
  <files>

  <action>
    1. Create src/pricing/engine.rs with PricingEngine struct:

    State:
    - config: PricingConfig
    - smiles: HashMap<NaiveDate, VolSmile> -- per-expiry vol smile, rebuilt on each update
    - iv_cache: HashMap<InstrumentId, IvCacheEntry> -- per-instrument latest (bid_iv, ask_iv, mid_iv, solver_results)
    - smile_points: HashMap<NaiveDate, Vec<SmilePoint>> -- raw IV data accumulated per-expiry for smile rebuilds

    IvCacheEntry struct (private):
    - bid_iv: f64, ask_iv: f64, mid_iv: f64
    - bid_solver: SolverResult, ask_solver: SolverResult, mid_solver: SolverResult
    - strike: f64, is_call: bool, forward: f64, time_to_expiry: f64

    PricingEngine::new(config: PricingConfig) -> Self

    PricingEngine::run(mut self, mut snapshot_rx: mpsc::Receiver<MarketSnapshot>, probability_tx: mpsc::Sender<ImpliedProbability>, cancel: CancellationToken):
    - Async select loop (biased: cancel first, then snapshot_rx).
    - On each Deribit option snapshot:
      a. Parse instrument name via pricing::instrument::parse_deribit_instrument. Skip non-options (futures, perpetuals).
      b. Extract forward price: use snapshot.underlying_price if available; else skip with warning.
      c. Compute time_to_expiry in years from parsed expiry to now. If below near_expiry_cutoff_hours, use intrinsic pricing path.
      d. Compute market mid_price from snapshot.bid and snapshot.ask (average). Also get bid_price and ask_price for bid/ask IV.
      e. Handle Deribit inverse option convention: option_price_usd = option_price_btc * forward_price_usd (the book prices are in BTC; multiply by underlying_price to get USD for Black-76).
      f. Call solve_iv_triple(bid_price_usd, ask_price_usd, mid_price_usd, forward, strike, time_to_expiry, rate, is_call, &config.solver).
      g. Update iv_cache with results.
      h. Update smile_points for this expiry: add/update SmilePoint for this strike.
      i. Rebuild VolSmile for this expiry from accumulated smile_points via VolSmile::new.
      j. Call extract_probabilities(strike, &smile, forward, time_to_expiry, rate, &config).
      k. Call compute_greeks(forward, strike, time_to_expiry, mid_iv, rate, is_call).
      l. Compute book_depth_usd from snapshot.depth_bids/depth_asks (sum top levels * underlying_price).
      m. Call compute_confidence(iv_spread, book_depth_usd, method_disagreement, solver_quality, &config.confidence).
      n. Assemble ImpliedProbability struct with all fields.
      o. Send via probability_tx.try_send (non-blocking, log if dropped).

    - Log at debug level: instrument, IV triple, probability, confidence, method, epsilon, skew.
    - Log at info level periodically (every 100 computations): pricing engine stats (total computed, mean confidence, Brent fallback rate).
    - Emit Prometheus metrics: counter "pricing_iv_solves_total", counter "pricing_brent_fallbacks_total", histogram "pricing_confidence", gauge "pricing_active_expiries".

    2. Near-expiry intrinsic pricing path:
       - When time_to_expiry < near_expiry_cutoff_hours / (365.25 * 24.0):
       - Probability = if is_call { if forward > strike { 1.0 } else { 0.0 } } else { if strike > forward { 1.0 } else { 0.0 } }
       - IV = 0.0, confidence = low (e.g., 0.3), method = IntrinsicOnly, near_expiry = true
       - Greeks: delta = intrinsic delta (1.0 or 0.0), vega = 0, theta = 0
       - Still emit ImpliedProbability (never silently drop per user decision)

    3. Add `pub mod engine;` to src/pricing/mod.rs.

    4. Write 3+ unit tests:
       a. Processing a Deribit option snapshot produces an ImpliedProbability
       b. Non-option instruments (futures) are skipped
       c. Near-expiry options produce IntrinsicOnly method with near_expiry=true

  <action>
    1. In main.rs, after the multi-venue pipeline setup and before the SpreadEngine:

    Add the PricingEngine as a parallel consumer of the fan-in snapshot channel. The current pipeline:
    ```
    [Multi-venue feeds] --snapshot_rx--> [SpreadEngine] --signal_tx--> [PaperTradeTracker]
    ```
    Becomes:
    ```
    [Multi-venue feeds] --snapshot_rx--> [SnapshotFanOut]
                                              |
                                              +--> [SpreadEngine] --signal_tx--> [PaperTradeTracker]
                                              |
                                              +--> [PricingEngine] --probability_tx--> (Phase 8 consumer)
    ```

    Implementation approach: Create a fan-out task that reads from the single snapshot_rx and forwards to both SpreadEngine and PricingEngine via two separate channels. This follows the existing fan-in pattern (Phase 4) but in reverse.

    Alternatively, since the PricingEngine only processes Deribit option snapshots, add a filter-forward approach: spawn a forwarding task that clones each snapshot, sends the original to SpreadEngine and the clone to PricingEngine. Use try_send for PricingEngine (best-effort, never blocks the spread pipeline).

    Steps:
    a. Create pricing engine channels: `let (pricing_snap_tx, pricing_snap_rx) = mpsc::channel::<MarketSnapshot>(1024);` and `let (probability_tx, _probability_rx) = mpsc::channel::<ImpliedProbability>(1024);`
    b. Create SpreadEngine's snapshot channel: `let (spread_snap_tx, spread_snap_rx) = mpsc::channel::<MarketSnapshot>(1024);`
    c. Spawn fan-out task: receive from `snapshot_rx`, clone, send to `spread_snap_tx` and `pricing_snap_tx.try_send()`.
    d. Update SpreadEngine to use `spread_snap_rx` instead of direct `snapshot_rx`.
    e. Spawn PricingEngine: `tokio::spawn(pricing_engine.run(pricing_snap_rx, probability_tx, pricing_cancel));`
    f. Note: `_probability_rx` is unused in Phase 7 (Phase 8 will consume it). Drop it explicitly or hold it to prevent channel close. Hold it in main scope so PricingEngine's try_send doesn't immediately get errors. Log at startup: "PricingEngine started (output buffered for Phase 8)".

    2. Import PricingEngine and ImpliedProbability from prediction::pricing.

    3. Add PricingConfig loading: already handled in Plan 07-01 Task 1 (added to SystemConfig). Access via `config.system.pricing.clone()`.

    4. Log at startup: "pricing engine started" with config summary (near_expiry_cutoff, iv_bounds).

    5. Ensure graceful shutdown: PricingEngine uses child_token from shutdown_token, same pattern as SpreadEngine and PaperTradeTracker.
  </action>
