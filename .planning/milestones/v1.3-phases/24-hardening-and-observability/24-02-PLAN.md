<objective>
Wire cleanup channels from SubscriptionManager into all five downstream stateful engines so unsubscribed instruments leave no stale state.

Purpose: After instruments are unsubscribed, their order books, snapshots, rolling stats, and IV cache entries must be evicted to prevent phantom spread signals from stale data paired with live data.

Output: Each of the 5 stateful engines (SpreadEngine, CrossAssetEngine, PricingEngine, DeribitProcessor, KalshiProcessor) receives a cleanup_rx mpsc channel and evicts entries matching removed instruments in a new select! branch.
</objective>

**SpreadEngine cleanup logic** (`src/spread/engine.rs`):
- `latest` is `HashMap<(String, Venue), MarketSnapshot>` -- retain entries where the event_id (tuple.0) is NOT in cleanup.event_ids. But since event_ids may be empty (Plan 01 sends empty Vec), use the per-venue instrument lists instead. Better approach: use ALL venue instrument lists to derive event_ids indirectly by retaining entries whose event_id still has active instruments in the registry. Actually, simplest: for SpreadEngine/CrossAssetEngine, use the `.retain()` approach from the research -- retain entries whose event_id is NOT in a "to_remove" set. Since we cannot reliably get event_ids from the cleanup event (they are empty), use the registry directly: acquire registry read lock, get active_approved() event_ids, retain only those.
- **Revised approach (per Research Pitfall 2):** When a cleanup event arrives, read the EventRegistry (already available as Arc<RwLock<EventRegistry>> on the engine) to get current active event_ids. Then retain only entries matching active event_ids:
  ```rust
  let reg = self.registry.read().await;
  let active_ids: HashSet<String> = reg.active_approved().map(|m| m.event_id.clone()).collect();
  drop(reg);
  let before_latest = self.latest.len();
  self.latest.retain(|&(ref eid, _), _| active_ids.contains(eid));
  let before_stats = self.stats.len();
  self.stats.retain(|eid, _| active_ids.contains(eid));
  tracing::info!(
      latest_removed = before_latest - self.latest.len(),
      stats_removed = before_stats - self.stats.len(),
      "SpreadEngine: cleaned up stale entries"
  );
  ```
- NOTE: SpreadEngine already has `registry: Arc<RwLock<EventRegistry>>` field. If it doesn't, check the actual struct definition and pass it through.

**CrossAssetEngine cleanup logic** (`src/signal/engine.rs`):
- Same pattern as SpreadEngine. Three HashMaps to retain:
  - `latest_prob: HashMap<String, _>` -- keyed by event_id directly
  - `latest_pred: HashMap<(String, Venue), _>` -- keyed by (event_id, venue)
  - `stats: HashMap<String, _>` -- keyed by event_id
- Use registry read to get active event_ids, retain matching entries, log counts.
- NOTE: CrossAssetEngine should already have `registry: Arc<RwLock<EventRegistry>>`. Verify from struct definition.

**PricingEngine cleanup logic** (`src/pricing/engine.rs`):
- `iv_cache: HashMap<InstrumentId, IvCacheEntry>` -- keyed by Deribit instrument ID. Use `cleanup.deribit_instruments` directly:
  ```rust
  let to_remove: HashSet<&str> = cleanup.deribit_instruments.iter().map(|s| s.as_str()).collect();
  let before = self.iv_cache.len();
  self.iv_cache.retain(|k, _| !to_remove.contains(k.as_str()));
  tracing::info!(
      iv_cache_removed = before - self.iv_cache.len(),
      "PricingEngine: cleaned up stale iv_cache entries"
  );
  ```
- Do NOT clean up `smiles` or `smile_points` -- per Research Pitfall 5, multiple instruments share an expiry date, and smiles expire naturally.
- PricingEngine does NOT need the registry -- it uses the instrument IDs from CleanupEvent directly.

For SpreadEngine and CrossAssetEngine: if these engines do NOT already have `Arc<RwLock<EventRegistry>>`, add the field and update the constructor. Check the actual struct definitions first. If adding registry is too invasive, fall back to using `cleanup.event_ids` (which Plan 01 leaves empty) and populate it in Plan 01's manager.rs by building a reverse map. But the research recommends registry .retain() approach as simpler.

**Alternative if registry not available on engines:** Build the event_ids list in the cleanup event. In src/subscription/manager.rs reconcile(), before updating current_* sets, iterate over removed instruments and look them up in the registry. But per Research Pitfall 2, removed instruments may no longer be in the registry. So maintain a HashMap<String, String> (instrument_id -> event_id) in SubscriptionManager that is populated from compute_desired_instruments. On removal, look up event_ids from this map. Add this map as a field on SubscriptionManager and populate it during reconcile(). This is "Option B" from the research and is the recommended fallback if engines lack registry access.
