Modify all three supervisors to accept a `watch::Receiver` for dynamic instrument updates. Each supervisor follows the same template with venue-specific type differences:

**DeribitSupervisor (supervisor.rs):**
1. Add `use tokio::sync::watch;` import
2. Replace struct field `instruments: Vec<String>` with `instruments_rx: watch::Receiver<Vec<String>>`
3. Update constructor `new()` to accept `instruments_rx: watch::Receiver<Vec<String>>` instead of `instruments: Vec<String>`
4. Change `run(self, ...)` to `run(mut self, ...)` (required for `changed()` which needs `&mut self`)
5. At the start of `run()`, before the backoff setup, call `self.instruments_rx.borrow_and_update();` to mark the initial value as seen (prevents spurious startup reconnect per Pitfall 1 in research)
6. At the top of the outer reconnect loop (after the cancel check), replace `self.instruments.clone()` with `let instruments = self.instruments_rx.borrow().clone();` -- the Ref is dropped immediately before any .await
7. Pass `instruments` (not `self.instruments.clone()`) to `DeribitClient::new()`
8. Add instrument count to the connecting log: `tracing::info!(attempt = attempt, instruments = instruments.len(), "DeribitSupervisor connecting...")`
9. In the inner `select!` loop, add a new branch between the cancel branch and the msg branch:
```rust
result = self.instruments_rx.changed() => {
    match result {
        Ok(()) => {
            tracing::info!("DeribitSupervisor: instrument list updated, reconnecting");
            backoff.reset(); // Intentional reconnect, not a failure
            break; // -> outer loop re-enters, reads updated list
        }
        Err(_) => {
            tracing::warn!("DeribitSupervisor: subscription channel closed, continuing with current instruments");
            // Channel closed (SubscriptionManager dropped). Continue operating
            // with current instruments. changed() will keep returning Err,
            // but biased select checks cancel first, so no busy loop.
        }
    }
}
```
