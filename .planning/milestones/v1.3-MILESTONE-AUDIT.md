## Tech Debt

### Phase 22: Subscription Manager Core

1. **Stale comment** — `src/subscription/manager.rs:301`: `event_ids: Vec::new(), // Populated by Plan 02 when wiring is complete`. Plan 02 is complete; `event_ids` was deliberately left empty because SpreadEngine/CrossAssetEngine use registry-retain instead. Comment should say: `// Unused: engines use registry-retain pattern instead`.

### Phase 24: Hardening and Observability

2. **Polymarket cleanup path absent** — `CleanupEvent.polymarket_token_ids` is populated but has no consumer. `PolymarketProcessor` is stateless (no per-market HashMap), so no stale state accumulates. If `PolymarketProcessor` ever gains stateful book tracking, a 6th cleanup channel will be needed. Alternatively, remove the field.

3. **Dead `PipelineHandles.subscription_rx` field** — Always `None` in live mode because receivers are consumed by supervisors during pipeline construction. Retained for potential future introspection but is currently dead code.

### Total: 3 items across 2 phases
