<task type="auto">
  <name>Task 2: Implement PredictionStack with all foundational resources</name>
  <files>infra/cdk/lib/prediction-stack.ts</files>
  <action>
Create `infra/cdk/lib/prediction-stack.ts` implementing the complete single-stack pattern from 34-RESEARCH.md. The stack must contain ALL of these resources:

**Network (INFRA-01):**
- `ec2.Vpc` with `maxAzs: 1`, `natGateways: 0`, single PUBLIC subnet (cidrMask 24). No NAT gateway -- saves $32/month. Single AZ required because EBS data volume is AZ-pinned.
- `ec2.SecurityGroup` with `allowAllOutbound: true`. Add NO inbound rules (SSM-only access, no SSH port). Comment explaining SSM is primary access path.

**ECR Import (INFRA-02):**
- `ecr.Repository.fromRepositoryName(this, 'EcrRepo', 'prediction')` -- import existing, do NOT create. Use `fromRepositoryName` not `fromRepositoryArn` (simpler, no hardcoded ARN).

**IAM Instance Profile (INFRA-04):**
- `iam.Role` with `assumedBy: new iam.ServicePrincipal('ec2.amazonaws.com')`
- Add managed policy: `AmazonSSMManagedInstanceCore` (remote management, no SSH)
- Add managed policy: `AmazonPrometheusRemoteWriteAccess` (future Phase 37 AMP)
- Use `ecrRepo.grantPull(instanceRole)` for ECR pull permissions
- Use `credentials.grantRead(instanceRole)` for Secrets Manager read
- Use `logGroup.grantWrite(instanceRole)` for CloudWatch Logs write
- Use `.grant*()` helpers everywhere -- they produce correctly scoped policies including non-obvious permissions like `ecr:GetAuthorizationToken`.

**EBS Data Volume (INFRA-05):**
- EC2 Instance with two `blockDevices`:
  - `/dev/xvda`: 20 GB GP3 root volume (default deleteOnTermination)
  - `/dev/xvdf`: 30 GB GP3 data volume with `deleteOnTermination: false` -- CRITICAL for data persistence
- Instance type: `t3.small` (sufficient for single container)
- Machine image: `ec2.MachineImage.latestAmazonLinux2023()`
- `associatePublicIpAddress: true`
- Add user-data commands to format and mount the data volume:
  - Check `blkid /dev/xvdf` -- format only if no filesystem exists (idempotent)
  - `mkdir -p /opt/prediction/data`
  - Mount and add to `/etc/fstab` with `nofail` option
  - Create subdirectories: config, spread_logs, settlement_logs, paper_trades, state, logs

**CloudWatch Log Group (INFRA-06):**
- `logs.LogGroup` with `logGroupName: '/prediction/production'`
- `retention: logs.RetentionDays.TWO_WEEKS` (14 days per requirement)
- `removalPolicy: cdk.RemovalPolicy.DESTROY` (log group is recreatable)

**Secrets Manager (INFRA-07):**
- `secretsmanager.Secret` with `secretName: 'prediction/prod/credentials'`
- `generateSecretString` with `secretStringTemplate` containing placeholder keys: DERIBIT_CLIENT_ID, DERIBIT_CLIENT_SECRET, DERIVE_WALLET_KEY
- `generateStringKey: '_generated'` (required field, value unused)
- Description: 'Venue API credentials for prediction system'

**Outputs:**
- CfnOutput for: InstanceId, EcrRepoUri, SecretArn, LogGroupName, VpcId

Follow the complete code example from 34-RESEARCH.md section "Complete Stack Structure" closely. Use the exact import style and construct IDs shown there.
