  <action>
1. In `src/config/system.rs`, add `pub stdout_json: bool` field to `LoggingConfig` struct (after `file_level`). This controls whether stdout emits JSON or human-readable format. Default should be false for local development (set in TOML config files), true in Docker via env var or production config.

2. In `src/logging/layers.rs`, change `init_logging` signature to accept `stdout_json: bool` as a fourth parameter. Use conditional logic to build the stdout layer:
   - If `stdout_json` is true: `fmt::layer().json().with_target(true).with_level(true).with_filter(stdout_filter)`
   - If `stdout_json` is false: `fmt::layer().with_target(true).with_level(true).with_filter(stdout_filter)` (current behavior)

   Because `.json()` changes the layer type (from `Layer<S, Format<Full>>` to `Layer<S, Format<Json>>`), you cannot use a simple if/else. Instead, use the boxed layer approach:
   ```rust
   use tracing_subscriber::Layer;

   let stdout_layer: Box<dyn Layer<_> + Send + Sync> = if stdout_json {
       Box::new(fmt::layer()
           .json()
           .with_target(true)
           .with_level(true)
           .with_filter(stdout_filter))
   } else {
       Box::new(fmt::layer()
           .with_target(true)
           .with_level(true)
           .with_filter(stdout_filter))
   };
   ```
   Then use `stdout_layer` (already boxed, implements Layer) in the Registry composition.

3. Update the call site in `src/main.rs` to pass `config.system.logging.stdout_json` as the fourth argument to `init_logging`.

4. Add `stdout_json = true` to the production TOML config file at `config/production.toml` (or whichever config is used in Docker). Add `stdout_json = false` to the default/development config. Check existing config files with `ls config/` and update all logging sections.

5. In `infra/cdk/lib/prediction-stack.ts`:
   a. Add CloudWatchAgentServerPolicy to instance role (after the existing `logGroup.grantWrite()` line):
      ```typescript
      instanceRole.addManagedPolicy(
        iam.ManagedPolicy.fromAwsManagedPolicyName('CloudWatchAgentServerPolicy')
      );
      ```
   b. In the user-data embedded docker-compose (the DCEOF heredoc), replace the `json-file` logging block with awslogs:
      ```yaml
      logging:
        driver: awslogs
        options:
          awslogs-region: us-east-1
          awslogs-group: /prediction/production
          awslogs-stream-prefix: prediction
          mode: non-blocking
          max-buffer-size: 4m
      ```
   Do NOT use `awslogs-create-group: "true"` -- the log group already exists via CDK.

6. The local `docker-compose.yml` in the repo root should KEEP `json-file` driver. The awslogs driver requires AWS credentials and would fail locally. No changes to the local compose file.
  </action>
