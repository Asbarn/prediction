**Check 1: At least 2 venue instruments for approved mappings.**

```rust
// Approved mapping safety: at least 2 venues required for cross-venue arbitrage
if event.approved {
    let venue_count = [
        event.venues.deribit.is_some(),
        event.venues.polymarket.is_some(),
        event.venues.kalshi.is_some(),
    ]
    .iter()
    .filter(|&&v| v)
    .count();

    if venue_count < 2 {
        return Err(ConfigError::Validation {
            file: "events.toml".to_string(),
            message: format!(
                "approved event '{}' has only {} venue(s) -- at least 2 required for cross-venue arbitrage",
                event.id, venue_count
            ),
        });
    }
}
```

**Check 2: Expiry not in the past for approved mappings.** This reuses the already-parsed expiry date (the earlier check at line 59 already validates the date format is parseable). Use strict less-than (`<`) so events expiring today are still valid (Deribit settles at 08:00 UTC -- an event expiring "today" should still be active until settlement).

```rust
if event.approved {
    if let Ok(expiry_date) = NaiveDate::parse_from_str(&event.expiry, "%Y-%m-%d") {
        let today = chrono::Utc::now().date_naive();
        if expiry_date < today {
            return Err(ConfigError::Validation {
                file: "events.toml".to_string(),
                message: format!(
                    "approved event '{}' has expired (expiry {} is before today {})",
                    event.id, expiry_date, today
                ),
            });
        }
    }
}
```

Add `use chrono::Utc;` at the top if not already imported (chrono::NaiveDate is already imported at line 2).

Add an async instrument-activity check in the lifecycle `poll_cycle` method. This runs after discovery data is collected and checks whether approved mappings have instruments that were NOT seen in the latest discovery results. This is the async complement to the synchronous validation in Task 1 (which cannot make API calls).

After the discovery data is collected (after `all_discovered` is assembled from all three venues, around line 420), add a check for approved-mapping instrument activity:

```rust
// Check approved mapping instrument activity against latest discovery data
{
    let registry = self.registry.read().await;
    let discovered_ids: std::collections::HashSet<(&str, &str)> = all_discovered
        .iter()
        .map(|d| (d.venue.as_str(), d.instrument_id.as_str()))
        .collect();
    // Note: Venue::as_str() may not exist -- use the Display or a match.
    // Actually, use a HashSet of (Venue, &str) tuples since Venue derives Eq + Hash.

    for mapping in registry.all_mappings() {
        if !mapping.approved || mapping.status != LifecycleStatus::Active {
            continue;
        }

        // Check each venue instrument
        if let Some(ref deribit) = mapping.venues.deribit {
            if !all_discovered.iter().any(|d| d.venue == Venue::Deribit && d.instrument_id == deribit.instrument) {
                tracing::warn!(
                    event_id = %mapping.id,
                    venue = "deribit",
                    instrument = %deribit.instrument,
                    "approved mapping instrument not found in latest discovery data"
                );
            }
        }
        if let Some(ref kalshi) = mapping.venues.kalshi {
            if !all_discovered.iter().any(|d| d.venue == Venue::Kalshi && d.instrument_id == kalshi.ticker) {
                tracing::warn!(
                    event_id = %mapping.id,
                    venue = "kalshi",
                    instrument = %kalshi.ticker,
                    "approved mapping instrument not found in latest discovery data"
                );
            }
        }
        if let Some(ref polymarket) = mapping.venues.polymarket {
            if !all_discovered.iter().any(|d| d.venue == Venue::Polymarket && d.instrument_id == polymarket.condition_id) {
                tracing::warn!(
                    event_id = %mapping.id,
                    venue = "polymarket",
                    instrument = %polymarket.condition_id,
                    "approved mapping instrument not found in latest discovery data"
                );
            }
        }
    }
    drop(registry);
}
```

Place this AFTER the three-venue discovery but BEFORE the fuzzy matching step (it's a read-only check on registry + discovery data, doesn't modify anything). This way the warning is emitted each poll cycle where the instrument is absent, which aligns with the existing absence-tracking philosophy (repeated warnings for persistent issues).

Important: Only check venues that were actually polled successfully in this cycle. If a venue poll failed (e.g., rate limited), skip that venue's check to avoid false warnings. Check whether the corresponding `deribit_instruments`/`kalshi_instruments`/`polymarket_instruments` vectors are non-empty before checking absence. If a venue returned zero instruments, that venue's poll likely failed or was skipped.

```rust
// Only check venues that actually returned data this cycle
let deribit_polled = !deribit_instruments.is_empty();
let kalshi_polled = !kalshi_instruments.is_empty();
let polymarket_polled = !polymarket_instruments.is_empty();
```

Then guard each venue check with the corresponding `_polled` flag.
