
Implementation steps:
1. Read `events.toml` fresh (same pattern as `batched_toml_write`)
2. Compute `today = Utc::now().date_naive()`
3. Get `retention_days` from `self.discovery_config.archive_retention_days`
4. Call `collect_archivable_entries(&doc, retention_days, today)` to get entries to archive
5. Call `collect_expired_unapproved_ids(&doc, today)` to get IDs of stale unapproved candidates
6. If both lists are empty, return `Ok(())` early (no file I/O needed)
7. **LIFE-01 archive step** (only if archivable entries exist):
   a. Derive archive path: `self.events_toml_path.with_file_name("events_archive.toml")`
   b. Read archive file content (or create default header string if file does not exist)
   c. Parse as `DocumentMut`
   d. Call `append_entries_to_archive_doc(&mut archive_doc, entries, &Utc::now().to_rfc3339())?`
   e. Write archive file using atomic write pattern (write to .tmp then rename):
      ```rust
      let archive_tmp = archive_path.with_extension("toml.tmp");
      tokio::fs::write(&archive_tmp, archive_doc.to_string()).await?;
      #[cfg(target_os = "windows")]
      { let _ = tokio::fs::remove_file(&archive_path).await; }
      tokio::fs::rename(&archive_tmp, &archive_path).await?;
      ```
   f. Log at INFO level: `"archived expired events"` with count and IDs
   g. Increment Prometheus counter: `metrics::counter!("lifecycle_events_archived").increment(count)`
8. **LIFE-02 cleanup step** -- combine both sets of IDs to remove:
   a. Collect all IDs to remove: archive entry IDs + expired unapproved IDs
   b. If unapproved entries exist, log each at WARN level: `"auto-removed expired unapproved candidate"` with event_id
   c. Increment Prometheus counter: `metrics::counter!("lifecycle_candidates_cleaned").increment(count)` for unapproved only
   d. Call `remove_entries_by_id(&mut doc, &all_ids_to_remove)?`
   e. Call `self.atomic_write(&doc.to_string()).await?`
9. Return `Ok(())`

Key design decisions per research:
- Archive write happens BEFORE removal from events.toml (archive-then-remove pattern from Pitfall 1)
- Unapproved candidates are removed directly (no archive) per research anti-pattern guidance
- The method reads events.toml fresh to minimize race window with operator edits
- Only performs file I/O when there are entries to process
