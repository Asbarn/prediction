Rewrite `src/bin/signal_scoring.rs` to replace the Phase 26 placeholder with full scoring analysis.

**CLI struct changes:**
- Change `--log-dir` default from `"signal_logs"` to `"settlement_logs"` (settlement data is the primary data source)
- Add `--settlement-dir` as the flag name (replacing `--log-dir`) to be explicit about data source. Keep default "settlement_logs".
- Keep all existing flags: --from, --to, --last, --output, --by-event

**Main function flow:**
1. Parse CLI args, create DateRange
2. Load settlement data: `range.files_in_dir_prefixed(&cli.settlement_dir, "settlements-")` then `load_jsonl::<AnalysisSettlementRecord>(&files)`
3. Print loading summary to stderr (file count, record count, errors) -- keep the loading info visible but don't mix it with scoring output
4. If records.is_empty(), print "No settled positions in range {range}" and exit 0
5. Compute aggregate scoring: `compute_scoring(&result.records)`
6. Render aggregate results using `render_output(&scoring, &cli.output, scoring_table)` for table mode or JSON
7. If --by-event: group records by event_id (HashMap), compute ScoringResult per group, render each group with event_id header

**Table rendering function `scoring_table(result: &ScoringResult) -> Table`:**

Use `new_table(&["Metric", "Value"])` and `set_numeric_columns(&mut table, &[1])`.

Build five sections using `section_header`:

Section 1 - HIT RATES (if hit_rates is Some):
- `section_header(&mut table, "=== HIT RATES ===", 2)`
- Row: `"Gross Hit Rate (n={total})"` | `"{rate:.1}%"`
- Row: `"  95% CI"` | `"[{lower:.1}%, {upper:.1}%]"`
- Row: `"  99% CI"` | `"[{lower:.1}%, {upper:.1}%]"`
- Row: `"Net Hit Rate (n={total})"` | `"{rate:.1}%"`
- Row: `"  95% CI"` | `"[{lower:.1}%, {upper:.1}%]"`
- Row: `"  99% CI"` | `"[{lower:.1}%, {upper:.1}%]"`

Section 2 - EDGE TEST (if edge_test is Some):
- `section_header(&mut table, "=== COST-ADJUSTED EDGE ===", 2)`
- Row: `"Mean Edge (n={n})"` | `"{mean_edge:.6}"`
- Row: `"Std Error"` | `"{std_error:.6}"`
- Row: `"t-Statistic"` | `"{t_statistic:.4}"`
- Row: `"p-Value"` | `"{p_value:.4}"` (or `"< 0.0001"` if very small)
- Row: `"95% CI"` | `"[{lower:.6}, {upper:.6}]"`
- Row: `"Significant (p < 0.05)"` | `"Yes" or "No"`

Section 3 - SHARPE RATIO (if sharpe is Some):
- `section_header(&mut table, "=== SHARPE RATIO ===", 2)`
- Row: `"Per-Trade Sharpe (n={n})"` | `"{per_trade:.4}"`
- Row: `"Annualized Sharpe"` | `"{annualized:.4}"` or `"N/A (single day)"`
- Row: `"Trades/Year"` | `"{tpy:.1}"` or `"N/A"`
- Row: `"PSR (P[SR > 0])"` | `"{psr:.1}%"` or `"N/A"` (display as percentage)

Section 4 - DRAWDOWN (if drawdown is Some):
- `section_header(&mut table, "=== MAXIMUM DRAWDOWN ===", 2)`
- Row: `"Max Drawdown (abs)"` | `"{max_dd:.6}"`
- Row: `"Max Drawdown (%)"` | `"{pct:.1}%"` or `"N/A"`
- Row: `"Peak Date"` | `"{peak_date}"`
- Row: `"Trough Date"` | `"{trough_date}"`
- Row: `"Recovery Date"` | `"{recovery_date}"` or `"Ongoing"`
- Row: `"Current Drawdown (abs)"` | `"{current_dd:.6}"`
- Row: `"Current Drawdown (%)"` | `"{pct:.1}%"` or `"N/A"`

**--by-event handling:**
When --by-event is set:
1. First render aggregate results as above
2. Group records by event_id: `HashMap<String, Vec<AnalysisSettlementRecord>>`
3. Sort event groups by event_id for deterministic output
4. For each event group:
   - Print a separator line and event_id header (table mode: println, JSON mode: nested in output)
   - Compute scoring for that group's records
   - Render the per-event scoring result

For JSON mode with --by-event, structure the output as:
```json
{
  "aggregate": { ScoringResult },
  "by_event": {
    "event_id_1": { ScoringResult },
    "event_id_2": { ScoringResult }
  }
}
```
Use a wrapper struct `ScoringOutput` with `aggregate: ScoringResult` and `by_event: Option<BTreeMap<String, ScoringResult>>` (BTreeMap for sorted keys in JSON).

**Error handling:**
- Use `anyhow::Result` for main
- Print parse errors count to stderr (as warning, same as current behavior)
- Do NOT panic on empty data -- display "No settled positions" and exit 0
