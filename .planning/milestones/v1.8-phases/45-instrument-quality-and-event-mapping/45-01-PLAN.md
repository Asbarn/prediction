<task type="auto">
  <name>Task 2: Build match-audit CLI binary</name>
  <files>src/bin/match_audit.rs, Cargo.toml</files>
  <action>
  1. Add `[[bin]]` entry to `Cargo.toml`:
     ```
     [[bin]]
     name = "match-audit"
     path = "src/bin/match_audit.rs"
     ```

  2. Create `src/bin/match_audit.rs` following the established CLI pattern from `spread_analytics.rs` and `signal_scoring.rs`:

  **CLI struct (clap derive):**
  - `--config-dir` (PathBuf, default "config") -- directory containing events.toml
  - `--output` (OutputFormat enum: table/json, default "table") -- reuse or define OutputFormat
  - `--issues-only` (bool flag) -- only show mappings with issues
  - `--spot` (Option<f64>) -- BTC spot price for moneyness checks. If omitted, skip moneyness validation.
  - `--expiry-tolerance` (Option<i64>) -- override default tolerance in days

  **Main logic:**
  - Load `events.toml` from config_dir using `prediction::config::load_events_config` (or the appropriate config loading function -- check what's public)
  - Iterate over `events` where `approved == true` and `status == Active`
  - For each EventMapping, perform these validation checks:
    a. **Venue count:** At least 2 venues present (polymarket + deribit/derive). Flag as ERROR if <2.
    b. **Strike alignment:** All venue instruments reference the same strike (already guaranteed by EventMapping.strike, so this is a consistency note)
    c. **Expiry alignment:** Parse expiry from each venue's instrument name (Deribit format: `BTC-28MAR26-75000-C`, Derive format: `BTC-20260328-75000-C`). Compare to EventMapping.expiry. Report gap in days. WARN if >3 days, ERROR if >expiry_tolerance (default 7).
    d. **Direction consistency:** Verify that option type (C for above, P for below) matches EventMapping.direction
    e. **Moneyness (if --spot provided):** Calculate `abs(strike - spot) / spot * 100`. WARN if >10%, ERROR if >25%.

  **Output (table mode):** Use `comfy-table` to render:
  ```
  Match Audit Report
  ==================
  Events checked: N
    Passed: X
    Issues: Y

  ID                     Strike  Dir    Venues  Expiry Gap  Moneyness  Status
  BTC-75000-2026-03-31   75000   above  PM+DB   4 days     10.3%      WARN: slightly OTM
  ```

  **Output (json mode):** Serialize a Vec of audit result structs with serde_json.

  **Exit code:** 0 if no ERRORs, 1 if any ERROR found.

  3. Reuse existing types from the prediction crate: `EventMapping`, `EventVenues`, `Direction`, `LifecycleStatus`, config loading functions. Do NOT duplicate logic. For OutputFormat, check if `prediction::analysis::output::OutputFormat` is reusable; if not, define a local enum.
  </action>
  <verify>
  `cargo build --bin match-audit` succeeds. `cargo run --bin match-audit -- --help` prints usage. Running against empty events.toml (`events = []`) reports "Events checked: 0" and exits 0.
  </verify>
  <done>
  match-audit binary compiles and runs. It loads events.toml, validates venue count, expiry alignment, direction consistency, and moneyness (when --spot provided). Supports table and json output. Exits 1 on validation errors, 0 otherwise.
  </done>
