<task type="auto">
  <name>Task 1: Create sensitivity analysis module</name>
  <files>src/analysis/sensitivity.rs, src/analysis/mod.rs</files>
  <action>
1. Create `src/analysis/sensitivity.rs` with:

   - `SensitivityResult` struct: `component_name: String`, `base_mean_net_edge: f64`, `slope: f64` (delta_net_edge per unit factor change), `impact_rank: usize`, `factor_results: Vec<(f64, f64)>` (factor -> mean_adjusted_net_edge pairs)
   - `SensitivityReport` struct (derives Serialize): `signal_count: usize`, `min_sample_warning: bool`, `results: Vec<SensitivityResult>`

   - Helper function `get_component_value(cb: &CostBreakdown, name: &str) -> f64` that pattern-matches on component name to extract the f64 value from `CostBreakdown` fields: "prediction_fee", "options_fee_estimate", "carry_cost", "prediction_slippage", "options_spread_cost", "basis_risk_premium". Returns 0.0 for unknown names.

   - `component_sensitivity(signals: &[ArbSignal], component_name: &str, factors: &[f64]) -> SensitivityResult`:
     - For each factor in `factors`, compute the adjusted net_edge for each signal:
       `adjusted_net_edge = signal.net_edge + original_component * (1.0 - factor)` (since increasing a cost component by factor means net_edge decreases by original * (factor - 1))
       Wait -- be careful with the sign. If `total_cost` includes `component` and we scale component by `factor`, the new total_cost = total_cost - component + component * factor = total_cost + component * (factor - 1). So new_net_edge = old_net_edge - component * (factor - 1) = old_net_edge + component * (1 - factor).
     - Compute mean adjusted net_edge for each factor
     - Compute slope via linear regression (use `analysis::stats::pearson_correlation` or simple (y_last - y_first) / (factor_last - factor_first)) between factors and mean net_edges
     - Store as `SensitivityResult`

   - `sensitivity_analysis(signals: &[ArbSignal]) -> SensitivityReport`:
     - If signals.len() < 20, set `min_sample_warning = true` (still compute, but flag it)
     - Default factors: `[0.5, 0.75, 1.0, 1.25, 1.5]`
     - Run `component_sensitivity` for each of: "prediction_fee", "options_fee_estimate", "carry_cost", "prediction_slippage", "options_spread_cost", "basis_risk_premium"
     - Sort results by `slope.abs()` descending (largest impact first)
     - Assign `impact_rank` (1-based) after sorting
     - Return `SensitivityReport`

   - `sensitivity_table(report: &SensitivityReport) -> Table`:
     - Using `analysis::output` helpers
     - Columns: "Rank", "Component", "Slope (d_edge/d_factor)", "At 0.5x", "At 1.0x", "At 1.5x"
     - If `min_sample_warning`, add a header row: "WARNING: < 20 signals -- results may be noisy"

   - Unit tests:
     - Test with synthetic signals where one component dominates -- verify it ranks first
     - Test with empty signals returns empty results
     - Test `get_component_value` extracts correct fields

2. Register `sensitivity` in `src/analysis/mod.rs`
